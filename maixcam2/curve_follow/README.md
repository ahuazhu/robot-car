# 小车应用

`main.py` 是 MaixPy 入口。应用源码是正常的 `robot` Python 包；本地测试与设备运行使用相同的导入关系。当前功能、接线、标定和参数说明见项目根目录的 [README](../../README.md)。

当前试版为 **v0.7.2-test.4**。仅第三项开启时，跳过近处道路曲率过小或反向的旧补偿门槛，修正弯中过早退出；仍按当前追踪／DWPP 转向目标分配并检查实际车身弧线。第三项“弯道按标定模型分配两轮”沿用 `bend_inner_reduction` 字段，从已测范围联合选择左右 PWM，短暂测速缺失且证据仍合格时按当前中线重新计算转向。三个开关默认关闭，重启后全关；本轮建议只开第三项，第一项保持关闭。全关对应 v0.7.1 驾驶控制基线，版本、界面和日志不要求与旧版逐字相同。

## 分层与状态归属

```text
curve_follow/
├── main.py                 # 设置计算线程数，启动应用
├── robot/
│   ├── application.py      # 组装组件、采集帧、连接输入与输出
│   ├── config.py           # 读取配置与统一参数边界
│   ├── core/               # 共享几何、运动变换、数值加速和道路策略
│   ├── perception/         # 原始图像 → 单帧道路边界与候选
│   ├── navigation/         # 时序道路模型、目标、转向与失路恢复
│   ├── tasks/              # 发车信号、横道礼让、计圈
│   ├── control/            # 驾驶会话、轮速、独立电机进程和UART
│   └── interface/          # 触屏、图像叠加、HTTP及网页资源
├── build.py                # 生成普通包和单文件安装器
├── tools/install_app.py    # 可独立验证的设备安装模板
├── calibration.json        # 当前镜头姿态的标定
├── runtime.json            # 当前驾驶和任务参数
└── curve_fit_kernel.c      # 可选的C99数值加速
```

- `perception.boundaries.CurvePixels` 负责光照处理、地面投影和单帧测量；不持有历史道路或驾驶状态。
- `navigation.tracker.TargetTracker` 将单帧测量与地面运动交给 `LocalRoadModel`。道路历史、确认窗口和置信度只由模型持有，已经删除旧的镜像字段和回灌接口。
- `navigation.steering_control` 选择实际前瞻目标并检查车身包络。几何锚点和驾驶目标分别记录，绘制层不修改导航结果。
- `navigation.road_recovery.RoadSearch` 协调恢复策略：有证据时使用已观测道路地图；证据不足且配置允许时委托 `BoundedVisualScan`。有限扫视独立持有脉冲、实际发送确认、停稳等待及重新确认道路的状态，不冒充已验证空间。
- `control.session.DrivingSession` 是应用层唯一的电机命令入口。手动STOP优先，然后处理启动或完赛、任务限制、恢复、爬升和租约；相机、触屏和HTTP均不直接发轮速。视觉发车和直接发车共用同一份启动检查。
- `tasks` 各自持有任务状态；网页和屏幕读取其快照。道路识别、任务停止和传输故障不互相替代。

当前固定场地的颜色互斥与预测反证由 `perception.surface.RoadSurfaceEvidence` 提供。保守模式可由连续明确绿色撤销历史；当前完赛优先模式保留中线，保留反证并降低中线置信度，由统一速度规划减速，等新观测确认后修正。白横纹、灰路面和未知区域不产生反证。回放结果及剩余限制见 [评估报告](../../docs/路面识别评估-20261104.md)。

核心几何的Python实现是原生库缺失时的回退，也是数值等价验证的参考，不属于无用代码。构建不再删除导入或拼接全局命名空间。

v0.6.86增加 `navigation.speed_observer.SpeedObserver`：只读当前连续可见路段，调用统一速度包络计算，并在 `/vision`、`/status` 的readiness与 `CONTROL` 日志发布同帧 `speed_profile_shadow`。`mode=SHADOW`、`controls_motor=false`；`source_frame`对应原始帧，`entry_limit_m_s`表示可见路段入口的分析上限，不是当前车速命令。道路不满足条件时明确标记无结果，不沿用旧结果。分析异常不向控制链抛出；耗时计入 `profile_ms.speed_profile_shadow` 及视觉预算。旧的巡线、横道、计圈、发车与看门狗逻辑保持，详见[在线对照记录](../../docs/统一速度规划回放-20261110.md)。

v0.6.88横道停车改用整车到横道的距离缩短速率，区分横向运动与实际接近。感知暂停不再进入已完成礼让流程；新鲜精确证据确认仍停在20cm外时恢复正常接近，只有合法停位与3.2秒实际停留均已验证才放行。取得合法停位后不因估计波动重新挪车。未启动的叠加显示 `PREVIEW`，感知暂停显示 `WAIT POSITION` / `WAIT MOTION`。定位、运动和停位回归见[修复记录](../../docs/横道远停与错误放行修复-20261110.md)。

v0.6.89将平顺接近与零输出制动分开：接近包络仍采用0.08m/s²，零输出后的制动模型依照19cm现场记录校正为0.20m/s²，保留0.35秒延迟。20cm合法停位判断与3.2秒停留要求不变，目标是一次刹停在10–15cm，不在停车后挪位。依据与验证见[制动校正记录](../../docs/横道制动校正-20261110.md)。

v0.6.90启用`speed_profile.mode=ACTIVE`：当前可靠道路的正常巡线由统一速度包络及实测速度反馈接管。横道、失路、预测和证据不足时保留基线控制，任务与硬件保护继续拥有最终输出。接管状态见`steering.speed_profile_control.selected`；原`speed_profile_shadow`继续只读。38秒基线保留为`baseline-v0.6.89`，实车对比按用户要求留到2026-11-11。详见[接管范围与回退](../../docs/统一速度规划接管-20261110.md)。

v0.6.91修正横道接近的决策：已确认事件通过实测地面运动持续更新车身到横道的距离区间，观测超过1秒、误差超过3.5cm或预测超过10cm不再单独清零轮速。误差从可用刹车距离中扣除，零输出取决于制动边界、真实运动缺失或合法停留阶段。零速回执、红灯与视觉静止一致时，不重复累积静止图像的运动噪声；实际位移仍更新位置。光流缺口按共享运动上限扩大位置区间，恢复后只有仍有刹车余量才继续。首次识别仍至少4条；已确认横道的3条可见条纹须匹配已有几何布局、位置与方向，并经多帧确认后才能重新定位，不能创建新事件或跳过停车。尚未取得合法停位、最近可能的横道仍留有刹车余量且道路可靠时，可恢复接近，无需等待再次出现完整条纹；合法停位取得后保持原地3.2秒，不对位挪动。新增`position_source`、`position_available`、`clearance_interval_m`和`tracking_hits`用于区分真实观测、运动推算、静止保持及部分条纹重定位。回归覆盖见`test_crosswalk_distance_authority`和`test_crosswalk_partial_tracking`；离线测试不代表实车停距已验收。

v0.6.92启用完赛优先恢复（`road_search.finish_priority=true`）：弱路径、切路和短时预测按原轮速比例限到逻辑峰值60；当前已见道路支持与转向指令有效时直接低速接回，不叠加第二次五帧等待。无路径时以每次0.12秒、逻辑峰值30执行四次一轮的左右探路；每轮最多6秒，未找到就要求新发零速指令和新鲜停稳回执再开始下一轮，不永久锁在EXHAUSTED。路沿车身余量冲突允许上述恢复转向，接受压路沿扣分，但不授权盲目前进。视觉静止与零速回执持续确认时，停稳间隔可缩短到0.25秒；缺失运动证据时仍等待0.75秒。每轮首转交替仅是搜索顺序，不证明实际姿态归零。横道停车、通信和时效保护、完赛及手动STOP仍有效。`round_index`、`total_pulses`、`CAUTIOUS`及`RETRY_WAIT`用于诊断。默认关闭此开关时保留原单轮策略；本次不改UNO协议，未启用后退或麦轮横移恢复。测试见`test_curve_finish_priority`与`test_session`；多轮实车脱困效果仍需验证。

v0.6.93在完赛优先模式中分开“候选道路确认”和“旧路线仍可继续使用”：新候选不能覆盖旧几何，仅沿仍有支持、误差和剩余行程预算的旧中线接续。光流失败时最多从最近实测刚体运动预测0.25秒，`valid=false`、`prediction_valid=true`明确区分；不能续签自己的时间、不刷新道路见到时间，不用于高速反馈、转向自学习或横道停稳证明。当前运行配置将历史行程上限由5cm调整为15cm，时间上限仍0.6秒，绿色反证、误差及车身检查仍有效；前进预测指令最长0.25秒，旋转仍不超过0.15秒，电机独立300ms零速、600ms失联保护保留。起步逻辑努力上升率从180调整到240PWM/s，速度参考加速从0.30调整到0.40m/s²，峰值和0.30m/s速度上限不变。ACTIVE时关闭旧SHADOW重复规划并输出明确DISABLED状态；实际速度规划继续逐帧。参见[分析与验证边界](../../docs/短暂漏检接续与提速-20261111.md)。

v0.6.94在进入寻路后也优先执行已经通过巡线层车身与预测预算检查的历史跟踪指令，保持低速与原预测租约，不再叠加新的当前画面确认等待。`speed_profile.high_confidence_gain=1.5`提高高置信直路追赶目标速度的力度：须持续确认道路、当前真实测速、观测质量至少0.75、当前无量纲转弯负荷不超过0.18、连续可见支持至少40cm，且实测速度低于规划参考。对照模式默认增益1.0；此增益同时加快参考速度爬升和正速度差反馈，合格路段参考加速由0.40升至0.60m/s²，不直接乘轮速。最高速度、外侧车轮、制动及PWM200上限仍有效；非目标条件与超速时使用原反馈。说明见[38秒记录与直路补油](../../docs/直路补油与预测恢复-20261111.md)。

v0.6.96修正v0.6.95遗留的4.8秒不确定性等待：横道位置或运动证明不足时立即进入`RECOVERY_PASSING`，逻辑峰值60，允许低速巡线或有租约探路，不先请求停车。`yield_completed`和`yield_verified`均保持假。明确位置发起的正常横道停车仍礼让3.2秒；若光流/红灯证明不全，同一次零速回执起算的3.2秒后低速继续并保留未验证，不再重复停留。视觉探路的0.75秒为真实转向脉冲之间的响应/看门狗等待，与横道不确定性等待分开；STOP、完赛、通信故障与启动授权保留。见[根因与完整审查](../../docs/完赛优先停车审查-20261111.md)。

v0.6.99将中线置信度接入统一速度包络，持续预测也可使用同一规划器。置信度综合观测质量、定位误差、新旧几何分歧、路面反证和路径支持长度；反馈失效时沿用同一比例限制轮速。取消固定恢复档及重复质量限速；模型保留与控制命令租约分开。几何错向使用通用航向对正，远候选不能覆盖当前路线。详见[参数与验证](../../docs/弯道出界与路线对正-20261111.md)。

## 现场设置圈数

网页控制台底部的“目标圈数”接受1–100的整数，默认取 `runtime.json` 的 `race.laps`（当前为2）。填写后点击ARM或直接启动，圈数随本次启动请求一起生效；ARM等待期间及行驶中锁定目标。需要修改时先STOP，再输入新值。设置仅保存在当前应用进程，应用重启后使用配置默认值。

现场准备集中在控制台完成：巡线默认显示叠加画面；ESP32 预览直接显示四条黄线，拖动线或圆点即可调整灯面范围。点击“ARM 准备等灯”会一次提交圈数和灯面设置，Maix 等待 ESP32 确认保存后再 ARM。无需单独编辑或保存；点击 ARM 立即锁定当前显示范围，实际检测也使用该固定范围，保存、等灯和行驶期间均不跟随新候选或检测网格移动。“自动定位”只启用辅助找灯，不会 ARM；“撤销调整”放弃本地草稿。准备、等灯或行驶中禁止继续修改范围；保存失败、超时或 STOP 均取消该次准备，不会因迟到保存回执重新 ARM。ARM、手动测试启动和 STOP 常驻底部；诊断入口在折叠区。STOP 后手动测试按钮自动恢复，无需刷新，灯框草稿不会锁住手动测试。启动条件未满足时点击会显示原因，服务端仍核对道路和电机状态。

触屏ARM沿用当前目标；视觉信号与直接启动共用计圈逻辑。实际发车后首次可靠识别的白线若在30秒内出现则忽略该次越线，否则首次实测越线计为第1圈；达到目标并确认最后越线后，按地面光流累计40cm实测前进行程，再直接停车。非法圈数不能触发启动，也不能阻止STOP。

## 本地验证

在项目根目录执行：

```sh
mkdir -p .maixpy/build
cc -std=c99 -O3 -fPIC -shared maixcam2/curve_follow/curve_fit_kernel.c \
  -o .maixpy/build/host_curve_kernel.so -lm
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  CURVE_NATIVE_LIBRARY="$PWD/.maixpy/build/host_curve_kernel.so" \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

将 `CURVE_NATIVE_LIBRARY` 指向不存在的文件可验证Python回退路径；原生专用测试会明确跳过。测试共享构造器放在 `tests/support/`，冻结的独立数值参考放在 `tests/reference/`，实拍样本及对应标定放在 `tests/fixtures/`。测试不得依赖 `.maixpy/` 下某台电脑的临时图片。

`test_application` 在模拟硬件边界执行完整预览帧；`test_session` 验证STOP优先、共同启动门槛、慢帧、失路探路租约、通信失败及完赛停车；`test_build` 离线验证部署包、安装回滚与未ARM启动。

三个实验开关的八种组合、停车确认、默认关闭与 STOP 互斥由 `test_control_experiments`、`test_application`、`test_session` 和浏览器脚本覆盖。组合接入测试不等同于驾驶输出的基线等价测试，也不代表实车压线已修复；本轮离线核验、打包和后续实测记录放在项目根目录 `.maixpy/v0.7.2-test.4/`。

## 构建与安装

```sh
.maixpy/.venv/bin/python maixcam2/curve_follow/build.py
.maixpy/.venv/bin/python maixcam2/curve_follow/build.py --drive
```

输出为 `.maixpy/build/curve_follow.zip` 及 `.maixpy/install_curve_follow.py` 或 `.maixpy/install_curve_follow_drive.py`。包内保留 `robot/` 的模块边界及HTML资源，不再生成 `standalone.py`。默认包强制预览；`--drive` 允许使用原配置的驾驶许可，仍默认未ARM。

通过MaixPy技能助手运行安装器：

```sh
./.maixpy/maixpy run .maixpy/install_curve_follow_drive.py --timeout 60
```

安装前由助手停止旧应用。安装器先暂存并检查文件、编译原生库并验证全部符号，再备份和替换本应用文件；注册或启动失败会恢复文件。安装后检查三个新帧及零输出，不自动发车。UNO固件独立烧录。

桌面显示名为 AAA，但启动器按应用 ID 排序。安装器将稳定 ID `robot_curve_follow` 加入 SDK 列表生成器的首个优先项，并核验生成后的顺序，避免后续部署时又排到后面；其余应用保持原有相对顺序。生成器原文随安装备份，安装失败时与应用列表一起恢复。实机修复记录见[AAA排序修复](../../docs/AAA排序修复-20261110.md)。

## 诊断与恢复

`/status` 提供运行和启动状态，`/vision` 原子发布完整当前帧、任务、道路证据及 `profile_ms`；任务快照每帧采集一次，在状态、日志和绘图之间复用。`/status` 的性能快照截止控制发布时，完整绘图与日志耗时见 `/vision`。`control_pipeline` 已包含算法子阶段，不能重复求和；`frame_period` 还包含帧间等待。预览原图、叠加图、地面投影分别用于检查可见性、识别与几何。
