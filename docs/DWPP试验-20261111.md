## 算法与接入

1. 原速度规划仍给出置信度、路径曲率、外侧轮速、路径末端制动和车身余量共同限制的速度上限。
2. DWPP在每周期可达到的前进速度 `v` 与转向角速度 `w` 区间中，寻找最贴近
   Pure Pursuit要求的 `w = curvature * v` 的组合；能精确贴合时选择最快前进速度。
3. 可行区域额外受到两侧轮速 `0 <= v ± 0.15*w <= 0.30` 的限制，普通巡线不要求内轮倒转。
4. 首次使用新鲜运动估计初始化，之后以上次通过任务限制和公共PWM斜坡后的参考为中心。
   未发送的提案不推进状态，STOP清除状态，寻路原地转向不冒充正常巡线状态。
5. 如果选出的转向与理想转向不同，重新检查该转向的车身扫掠；需要进一步减速时整体缩放两轮，保持曲率。
   新旧中线交接时同时检查两条路线。
6. 突然降低的置信度/车身限速优先于名义加减速窗口，不为维持窗口而抬高上限。
   例外明确记录为 `LINEAR_BRAKING`、`ANGULAR_BRAKING` 或 `BODY_SWEEP_BRAKING`。
   完赛优先模式继续保留触边时的原低速恢复参考，不增加限时等待。

没有有效测速、可信前进位移或可执行窗口时，继续使用基线已有的受置信度和车身限速约束的PWM控制/寻路。
横道等任务拥有速度时不启用DWPP。STOP、完赛、串口与图像时效约束保持优先。
转向偏差学习使用DWPP实际选出的曲率，避免把有意限制的转向误学成电机偏差。

## 参数与局限

`runtime.json` 的 `speed_profile` 增加：

| 参数 | 试验值 | 用途 |
| --- | --- | --- |
| `controller` | `DWPP` | 可改为 `PURE_PURSUIT` 使用基线控制律 |
| `angular_acceleration_rad_s2` | 2.0 | 参考转向角速度上升速度 |
| `angular_deceleration_rad_s2` | 2.0 | 参考转向角速度回落速度 |

两个角加速度是待实车校验的工程初值，尚未通过电机动态标定。前进加速度0.40m/s²、
高置信度增益2.0和其余原参数保持不变。越高的角加速度越接近原来立即追求理想曲率的行为；
过低可能拖慢入弯，过高则失去限制不可达转向变化的作用。

本车没有轮速编码器，也没有独立角速度闭环；最终仍由原前进速度反馈调节平均PWM，
按DWPP结果分配两侧比例。因此窗口限制的是**名义速度参考**，不保证实际轮速或车体角加速度严格满足数值。
公共PWM斜坡后参考的估计亦属命令域估计。车身扫掠在第一步之后继续采用原几何追踪预测，
不是完整电机动态仿真。试验不提供已验证的圈速提升或压线率下降承诺。

## 验证

完整回归1,014项，1,010通过、4项按原条件跳过。新增16项DWPP验证包括：
二维窗口解析解、左右对称、快速反向转弯、250组随机窗口与独立密集采样对照、
轮速多边形、强制降速、实际发送状态、STOP及寻路状态重置、低置信度慢行、
实际曲率车身检查、偏差学习隔离，以及原斜坡/电机死区/延迟条件下的反馈收敛。

接入时还修正了旧车身扫掠的首段计算：原循环在第一次前进前重算理想曲率，导致传入曲率被覆盖。
普通Pure Pursuit传入的本来就是该理想曲率，DWPP则可能不同，因此必须让第一次推进真正使用传入值。
独立回归用同一条道路、不同首段转向证明车身投影及风险结果确实变化，不能只验证函数被调用。

对本机两段历史赛道日志共583份普通巡线快照做开环比较：两种控制都不超参考上限或PWM200。
DWPP选中342份，其中141份可直接贴合理想曲率、201份受窗口约束；
65份记录线速度制动优先、3份记录角速度制动优先。约束例外不是被隐藏的违规。
记录为事件采样，控制提案改变后下一帧仍使用旧实测位置；不能由快照计数、参考速度分布或
两种控制的接管数量推断实际运行时间、圈速和压线概率。

复现工具：`maixcam2/curve_follow/tools/replay_dwpp.py`，接受遥测JSON数组或CONTROL日志，
必须显式指定输出文件。它不连接设备；横道控制阶段被排除，非闭环行驶仿真。
完整本机结果位于 `.maixpy/dwpp-20261111/`。

Maix上256组窗口数值自检通过，另验证真实车身扫掠会采用选定的首段转向。
单独窗口求解中位数约0.227ms、该批最大11.51ms；这是应用运行时的独立探针，
含调度影响，不代表整个控制周期或额外车身扫掠的耗时。

## 部署与回退

通过项目构建器生成正常驱动安装器后，仅在未ARM、非运行、零输出状态安装；安装后仍未ARM。
相机、ESP32与UNO固件无需更新。本次先完成部署与数值自检，实车启动由现场人员操作。
最终安装记录为 `.maixpy/runs/20261111-151752-install_curve_follow_drive/`，
确认v0.6.102首次画面持续更新、未ARM、两轮输出为零、UNO正常回执且日志无异常栈。
20份关键设备文件与构建源码哈希一致，标定文件哈希与基线相同。
同一段赛道应同时记录计时、压线次数和转向修正次数，不能只以瞬时最高PWM判断收益。

轻量回退：将 `speed_profile.controller` 改为 `PURE_PURSUIT` 后重新构建部署。
完整回退：从 `baseline-v0.6.101-pre-dwpp` 构建，或使用本机baseline目录内保存的原安装器。
回退或部署均应先STOP，不自动发车。
