# DWPP 摇摆修复与审查 — v0.6.109

## 问题与实际修正

v0.6.108的末段左右摇摆中，24条已记录控制样本均由DWPP输出，UNO通信正常。路线在单左边、单右边、双边观测与历史预测之间出现方向冲突；动态窗口却优先使用上一条指令对应的理想速度，即使光流提供了有效的实际转速。车身尚未结束原来的转向，控制器已经允许反向纠偏。

v0.6.109保留DWPP唯一巡线入口，修正其状态输入与约束衔接：

| 环节 | 修正后的行为 |
| --- | --- |
| 窗口初值 | 有效实测车身速度、转速优先，上一条命令不能覆盖测量 |
| 小前进位移 | 有效光流仍可提供窗口初值；单独禁止无法分辨前进位移时的速度积分，限制参考速度不超过0.075m/s |
| 短暂光流缺失 | 从最近运动状态向已应用参考速度按执行器响应时间预测，明确标为ESTIMATED；不当成实测，不用于道路/横道里程积分 |
| 控制间隔超限 | 撤销旧命令连续性，使用短窗口、低速上限，但不把新鲜实测转速改成零 |
| 中线冲突后恢复 | 置信度下降立即生效；速度规划用的置信度上升按0.8s时间常数渐进。只有当前已接受观测可恢复；同一时刻重复计算、预测帧、长间隔不能累积恢复时间 |
| 路线切换 | 保留观测几何，不平均两条冲突路线；以实测状态建立的DWPP窗口约束输出转向过渡，恢复期保持较低速度 |
| 实际超速 | 测量允许超过命令上限，由求解器给出明确的制动覆盖，不能截断传感器数据或抛异常退出 |
| 跨零反向 | 先计算原方向减速至零所需时间，剩余时间才用于反向加速；兼容不同角加速度/减速度配置 |
| 侧向加速度 | 检查DWPP实际选择的弧线，而不只看原始中线曲率；超过限制时共同缩放线速度、角速度，保留弧线比例并记录LATERAL_BRAKING |

控制置信度独立于原始道路置信度，状态同时输出`raw_centerline_confidence`和`centerline_confidence`。下降无延迟，恢复不额外停车。没有提高巡航速度、转向增益或PWM上限；计圈仍暂停，测试结束需STOP。

## 源码审查范围与算法差异

对照[Nav2 DWPP原实现](https://github.com/ros-navigation/navigation2/blob/main/nav2_regulated_pure_pursuit_controller/include/nav2_regulated_pure_pursuit_controller/dynamic_window_pure_pursuit_functions.hpp)检查窗口初值、追踪直线与可行域求交、无交点时的最近点选择。

本项目的固定尺寸凸多边形求解器仍按`w=k*v`选择最快的精确交点，无交点则最小化偏差。项目另外加入非负轮速及轮速上限，所以可行域不是原版的单纯矩形。保留以下有意差异：

- 任务停车、道路置信度/车身限速可覆盖常规减速度窗口；覆盖会记录原因，不能声称此时仍满足所有动态可达性约束。
- 尖锐追踪曲率限制在前进轮速锥内，避免从静止时只选零解；实际弧线继续由车身包络检查。
- 当前不提供独立车轮测速，轮速映射和命令比例只是近似；算法约束的是参考速度，不能保证车身精确执行。
- 本次新增检查实际选择弧线的侧向加速度；共同缩放同样属于显式制动覆盖。
- 修正旧回放工具中残留的PWM200断言，使用与固件一致的MAX_MOTOR_PWM（255）。

## 验证

- 针对性测试63项通过；完整回归1074项通过（45.130s）。
- 新增9项测试覆盖现场反打、有效转速与前进积分分离、缺测估计连续性、长间隔、置信度恢复/重复调用/跨帧率、侧向限幅、硬停车、超速、跨零反向加减速。
- 额外10000组随机超速/非对称角加减速输入：无异常，可行解均满足前进轮速范围及参考限速。
- 对刚才日志中198条有效实测运动样本做独立单步回放，保持每条原始速度上限和控制间隔不变：按设定角减速度尚不能转正、却已输出反向角速度的样本，从8条降至0条。

| 帧 | 实测转速 | 旧窗口采用转速 | 旧输出 | 用实测状态求解 |
| --- | ---: | ---: | ---: | ---: |

这些数据是固定原始运动与约束的单步计算，不是修改后实车轨迹，也不是“摇摆次数下降8次”的证明。CONTROL日志是稀疏样本，没有整段逐帧原图，尚不能确定中线反复变化分别有多少来自白边识别、运动补偿和融合拟合。实际压线、摇摆和圈速仍须同段实车复测。
