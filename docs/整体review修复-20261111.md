# v0.6.105：巡线、寻路、DWPP和横道逻辑修复

基于v0.6.104（`ec270c8`）的整体review。复现与测试输出位于本机
`.maixpy/review-20261111/`、`.maixpy/fix-review-20261111/`。
本轮修复控制链中的冲突，不进一步提高轮速或转向增益，不改变标定。

## 六项修复

1. **寻路不能覆盖有效的低置信慢行。** 原`ALIGNING`分支根据保留路线方向持续更新
   原地旋转指令，可将低置信巡线替换为左右±60的逻辑PWM。删除这个独立输出分支，
   有效置信度限速下的巡线/刹车指令优先；确实没有可执行目标时，方向信息只给既有
   有界左右脉冲提供方向提示。恢复力度也随置信度降低，保留最小探路力度与脉冲/停稳确认。
   历史中线继续保留，不能恢复为无限续期的原地旋转。
2. **已经礼让的旧横道不能误认下一次横道。** `PASSING`需要短遮挡、连续部分条纹
   或误差受控的连续运动传播证明事件仍能定位。失去这些证据后，即使新观测方向/距离接近，
   也重新确认新事件；旧事件不再向新观测借用“已完成礼让”许可或三条纹模板。
   连续定位仍成立时，不重复停车。此修复针对已合规礼让的`PASSING`；`RECOVERY_PASSING`
   的未验证释放仍保留既有防二次长停语义，不声称已解决任意失定位情况下的跨圈事件识别。
3. **轮速在最终下发时才取整。** 巡线、任务缩放、车身限速和公共加速斜坡保留浮点比例，
   最后经过启动补偿再转为串口整数。复现中请求曲率1.896，提前取整使指令曲率约1.296；
   修改后约1.891。这里是指令比例推算，不是实测车身曲率。DWPP下轮状态采用最终下发比例，
   调速器的力度反馈仍使用逻辑PWM单位，避免把启动补偿混入积分量。
4. **大转向由DWPP选择可执行速度。** 旧PP的严格曲率可行性门槛只作用于PP，不能在
   DWPP求解前直接回退到旧的单轮急转。DWPP在速度与角速度窗口内选可执行方案，再检查
   实际选择轨迹的车身余量。端点、置信度、制动和车身限速继续生效。
5. **未接受的新观测不能提高旧中线的置信度。** 候选仍在等待确认时，只能保留或降低
   当前观测一致性；只有接受相容观测后才按原规则逐步恢复。避免一个较轻的冲突候选在
   尚未更新几何时把置信度重新抬高。
6. **故障停用时间不能补算横道停留。** 未完成的STOPPING/HOLD/RECOVERY_HOLD在任务
   停用时清除连续物理停稳、零回执、红灯停留和位置证明，恢复后重新计时。保留事件身份；
   已完成礼让的PASSING不受影响。手动STOP仍遵循原来的任务重置。

## 两项优化

- 道路样本携带各自的不确定度。当前跟踪前段与车身扫掠使用所处路段的误差，避免远处
  未更新尾段的最大误差压低当前新鲜路段的速度。真正进入高误差路段仍限速，缺失有效
  逐点误差时保留原有保守标量回退。
- 每次车身扫掠仍检查7个位置，但仅重算5次后续追踪点，移除首尾两次无效计算。
  本机15组左右弯/直道结果一致；交替测试7轮，扫掠函数中位耗时1663→1401微秒，约减少15.7%。
  这是单函数主机基准，不是Maix整帧提速，也不是圈速收益。

## 验证与操作边界

- 使用本轮重新编译的原生内核，完整1048项回归通过，无跳过。
- 版本和界面收尾后，横道生命周期、打包、预览连接24项检查通过。
- 新增真实调用链回归覆盖轮速补偿、DWPP大转向、置信度交权、历史远尾误差和横道身份/停留。
- 运行参数和标定不变。横道礼让仍为3.2秒；计圈仍暂停，试跑须手动STOP结束。
- 实车路线、横道距离、压线和圈速收益需同段复测；离线测试不能替代这些测量。
- 构建包为`.maixpy/build/curve_follow.zip`；部署前检查未ARM、任务停止及零输出。
