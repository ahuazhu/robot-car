# 现场控制台

源码版本：Maix 0.6.82 / ESP32 0.4.14-http-lamp-config。

## 现场流程

1. 在同一局域网打开 `http://maixcam2-e1fa.local:8000/`。左侧摆正巡线画面，右侧确认信号灯。
2. 灯灭时确认灯面：自动模式显示新鲜模型候选；已有手动范围则优先显示保存范围。直接拖动画面上的四条黄线或圆点，只圈灯面，避开数字屏与漏光。没有单独的编辑或保存步骤；“自动定位”只开启辅助找灯，不 ARM；“撤销调整”放弃本地草稿。
3. 设置底部目标圈数，按“ARM 准备等灯”。按下时立即锁定当前可见框的位置，本次请求先保存该固定范围，ESP32 确认生效后再进入等灯；裁判亮灯后再次熄灯，小车按原有许可与道路、电机检查自动出发。
4. STOP 常驻底部；状态、性能参数和跳过等灯的手动测试入口收在折叠区。

巡线默认放大显示叠加画面，可以切换原图、投影、三图。新界面首次不继承旧版自动保存的三图默认值，此后记住选择。窄屏将两路画面纵向排列，比赛操作仍固定在底部。

ARM 与 STOP 采用相同按钮高度（常规 56px、手机 48px）。平板及手机把状态文字独立放在上排，两个按钮在操作排底部对齐；圈数换行不再把 STOP 抬到状态区中间。此布局补充复跑页面脚本回归与应用构建。

## 配置与互锁

网页 ARM 通过同源 `POST /control` 一次提交圈数及 `lamp_configuration={manual:true,roi:当前可见框}`，沿用随机控制 token 与 generation。Maix 在本地保留最长 5 秒的准备请求，配置保存仍由 ESP worker 异步执行，不在行车循环等待网络。只有本次 request_id 对应 SAVED、设置一致、同 generation、状态及时、停车未 ARM 且 ESP 就绪时，主循环才交付一次原 ARM 请求，圈数采用提交时的值。固件与模型沿用 0.4.14。自动定位只提供 ARM 前候选；按下后 UI 始终显示捕获的原始坐标，实际检测也固定在该范围，不随模型候选或内部采样网格变化。准备失败时框仍固定，可同框重试；STOP 或本轮完赛停车后解除。

STOP（含触摸 STOP）优先取消准备。保存失败、超时、配置或回执变化、源状态过期均不 ARM；迟到保存回执也不会重新准备。配置在途的 NVS 写入可能已经完成，取消准备不会回写旧范围。网页草稿保留，可再次明确按 ARM。SVG 辅助线改用属性显隐，修复曾因 SVG `.hidden` 不反射属性而一直被隐藏的问题。线条、圆点和键盘方向键均可调整边界，最小范围保持 16×16。

独立 `POST /lamp-config` 接口保持兼容；其本身不产生出发许可。“自动定位”在当前为手动模式时，通过该接口切到 `manual:false` 恢复 ESP 模型找灯，匹配保存回执前锁住编辑和 ARM；成功后候选可更新。已在自动模式则不重复写入。自动定位没有新鲜候选时可先手工拖框，ARM 再统一保存固定范围。自动模式继续保留最后一个手动范围。

自动候选只是准备提示：合法 ROI、模型自检通过、来源不超过 2500ms；Maix 缓存经过时间计入年龄。候选不会替代正式发车证据，手动范围始终优先。

此次不改灯光判断阈值、标定、巡线速度、横道停留或计圈距离。
