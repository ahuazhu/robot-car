# 现场控制台

源码版本：Maix 0.6.80 / ESP32 0.4.14-http-lamp-config。

## 现场流程

1. 在同一局域网打开 `http://maixcam2-e1fa.local:8000/`。左侧摆正巡线画面，右侧确认信号灯。
2. 灯灭时确认灯面：自动模式显示新鲜模型候选；已有手动范围则优先显示保存范围。点击“调整灯面”，拖动四条黄线或使用边界滑条，只圈灯面，避开数字屏与漏光，再点击“保存灯面”。也可在调整区恢复自动定位。
3. 设置底部目标圈数，按“ARM 准备等灯”。裁判亮灯后再次熄灯，小车按原有许可与道路、电机检查自动出发。
4. STOP 常驻底部；状态、性能参数和跳过等灯的手动测试入口收在折叠区。

巡线默认放大显示叠加画面，可以切换原图、投影、三图。新界面首次不继承旧版自动保存的三图默认值，此后记住选择。窄屏将两路画面纵向排列，比赛操作仍固定在底部。

## 配置与互锁

浏览器仅向 Maix 同源 `POST /lamp-config` 提交设置，使用现有随机控制 token 和 generation。Maix 的 ESP worker 通过原配对密钥在 81 端口执行 `POST /signal` 的 `configure` 操作，不在行车循环等待网络。ESP 再次校验密钥、boot 与正式 ARM 状态后，写入并回读 NVS。自动模式保留最后一个手动范围。

保存操作不能产生出发许可。未保存草稿、配置请求在途、正式等灯或行驶中均锁定相应操作。会话层也拒绝配置在途的直接启动，覆盖触摸与绕过浏览器的请求。页面仅在收到本次 request_id 对应的 SAVED 状态且设置一致后解锁；旧保存回执与旧错误不能完成新请求。

自动候选只是准备提示：合法 ROI、模型自检通过、来源不超过 2500ms；Maix 缓存经过时间计入年龄。候选不会替代正式发车证据，手动范围始终优先。

此次不改灯光判断阈值、标定、巡线速度、横道停留或计圈距离。

## 验证

802 项自动回归通过，包括实际页面脚本的连接、草稿、配置保存回执与操作互锁，以及 ESP 配置处理路径的 C++ 回归。Maix 包与 ESP 实际固件编译通过，模型权重和灯光阈值未改。

设备部署结果单独记录。浏览器自动访问该页面未获权限，未进行真实浏览器截图或触摸手感验收；Node DOM 回归不代表真实排版验收。
