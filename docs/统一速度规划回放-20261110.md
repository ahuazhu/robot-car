# 统一速度规划：第一阶段离线实现

本次完成可执行的路径速度规划器、动力参考插值和历史日志回放。**没有接管正式电机输出，没有部署新的行车控制。** Maix 正式应用仍为 v0.6.85；木地板测量没有覆盖赛道制动、低速死区或转弯动力学。

## 分工与算法

- 道路模块提供有支持的路径、曲率、误差和车身可通过范围；不能把不可见的断口连接起来。
- 任务模块提供横道或终点的停车位置，继续负责停留、计圈和出发许可。
- `robot/navigation/speed_profile.py` 在路径上计算一个速度包络：外侧轮速度上限、横向加速度、前方停车距离共同约束；从后向前计算制动，再从前向后计算加速。复杂度与路径点数成正比。
- 电机闭环和 STOP／通信看门狗仍是独立职责。本阶段没有改写现有 `SteeringControl`、横道调速或 PWM 爬升，避免形成两套同时生效的限速链。

核心物理关系：弯道横向加速度为 `v² × |曲率|`；直线停车需要 `v × 延迟 + v² / (2 × 制动减速度)`。规划器只在入口计一次延迟，不能每经过一个路径点就再扣一次，否则增加采样点会错误地把车速压低。

停车点会插入到准确的路径距离处，绝不向后取整；支持路径的尽头也是零速边界。距离误差从可用路程中扣除。已经超过入口速度上限时明确报告 `initial_overspeed`，不把瞬间减速画成可实现轨迹。本实现是离散标量速度包络，不是完整 TOPP-RA、MPC 或已验证的连续车身轨迹优化器。

## 动力数据的使用范围

`tools/drive_reference.py` 读取[五档实测参考](动力测量参考-20261110.json)，输入是 **UNO 实际 PWM**，不能把加峰值补偿前的逻辑 PWM 当作实测档位。

150／180 的小幅倒挂用公开记录中的单调参考平台处理，反算同一速度时选较低档位150；原始测量不修改。只在实测90–200区间内插值，区间外返回“不支持”。零速、低速、倒车、转弯左右轮和电池变化的动力关系尚未识别，不能靠这张表伪造完整电机模型。

## 回放结果

输入为四份已有记录，计2756帧，其中2119帧处于活动状态。474段满足“当前观测、连续可见、几何及误差有效”的条件；1314帧因非当前观测／无有效目标／待确认等被排除，另331帧没有足够连续支持。这些是回放筛选计数，不等同于实车故障次数。

| 入口主要约束 | 段数 |
| --- | ---: |
| 可见路段终点及停车余量 | 420 |
| 名义差速模型的外侧轮速度 | 42 |
| 横向加速度／曲率 | 4 |
| 曲率超出仅前进的名义转向范围 | 8 |

默认参数：速度上限0.30495m/s取自本轮PWM200参考；制动减速度沿用现有0.08m/s²；延迟保守取控制新鲜度0.35秒加现有响应0.4秒。横向及前向加速度暂按0.15m/s²分析，尚未实测。扣除车头余量0.075m和两倍记录误差后，支持路程中位数约0.446m，段入口速度上限中位数约0.205m/s。

**段入口是第一处可见路径点，不是小车当前位置。** 这些日志多数没有覆盖车到第一点之间的道路。回放没有穿过这个缺口，也没有模拟车身包络、任务停留、预测道路、搜索、通信或新策略改变后的轨迹；不能由此计算圈速收益或直接生成驾驶命令。历史投影保留各自标定，没有按木地板测距统一缩放。

作为参数敏感性分析，假设制动能力为0.20m/s²、其余不变，段入口上限中位数为0.256m/s；只把延迟假设改为0.35秒时为0.228m/s。两者均为假设，**没有写入正式参数，也不是实车提速成绩**。当前0.08m/s²与0.75秒组合下，0.305m/s停车需要约0.81m有效路程，还未计车头和测距余量。因此下一步应核实制动／延迟并改善有效预判距离，继续提高PWM不能解决这些约束。

已有记录中，等速左右PWM均落在新参考表90以下，其余是转弯输出。回放没有为它们外推“旧车速”，也没有据此捏造新旧圈速对比。

## 性能与验证

Maix 上独立运行同一纯计算模块，正式应用未退出或重启；每种点数预热20次、计时101次。几何拟合、相机、任务和电机不在此计时内。

| 路径点数 | 规划中位耗时 | P95 |
| --- | ---: | ---: |
| 20 | 0.59ms | 2.51ms |
| 40 | 1.03ms | 2.67ms |
| 80 | 2.01ms | 7.99ms |

并发正式视觉循环使耗时有调度波动，80点最大值11.15ms，不能将中位数当硬实时保证。完成后重新检查：未ARM、未发车、左右输出0、UNO零速回执正常、刹车灯亮。

新增15项测试覆盖：未来弯道提前限速、加速／制动不等式、延迟与采样密度、准确停车点、误差余量、初始超速、实测插值边界、历史及断口不得变成当前道路。启用当前C原生核后，全套866项Python测试通过。

可从仓库根目录重放公开的小样本：

```sh
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  .maixpy/.venv/bin/python maixcam2/curve_follow/tools/replay_speed_profile.py \
  tests/fixtures/curve_oscillation.json --include-frames \
  --output .maixpy/speed-profile-20261110/public-fixture.json
```

公开样本46帧，其中16段可评估。四份完整输入及完整报告仍存本机 `.maixpy/speed-profile-20261110/`；另外三份输入为 `.maixpy/stopped-20261107-115708/controls.json`、`.maixpy/left-turn-20261107-113022/controls.json`、`.maixpy/stutter-20261107-110729/post-v068/controls.json`。脚本同时支持含 `CONTROL {...}` 行的日志。`--deceleration`、`--delay` 只改变本次离线分析，报告会标记显式假设；不会修改设备或配置。

## 后续接入

先把现有车身包络、当前路径接续和任务停车点转换成统一规划输入，在线旁路记录新旧参考速度，保持原电机输出；核对制动和延迟假设后，再让单一速度闭环接管，逐步删除原有重复的PWM限速。正式接管前还需处理90以下参考缺口、实测速度与投影尺度误差、曲率与两侧轮速关系。届时再做赛道对比，本轮不用继续测PWM250，UNO实际输出上限仍为200。
