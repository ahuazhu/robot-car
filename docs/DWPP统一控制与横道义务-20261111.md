# v0.6.107：DWPP统一控制与横道停车义务

## 已确认的问题

v0.6.106这轮首次弯道的CONTROL日志中，横道在frame368出现，frame370确认，frame371光流失败后进入RECOVERY_PASSING；直到人工STOP都未进入正常停车停留。横道位置误差随后扩大，缺少新条纹观测时再也没有恢复APPROACH。

另一条独立问题是职责重叠：横道存在时allows_speed_profile关闭整个DWPP，转向也切回target_command；速度无法从位移噪声中分辨时也切回旧算法。横道另有PWM积分调速器，覆盖上游规划。日志能证明这些切换存在，但不能仅凭稀疏记录断言它们解释全部实体摆动。

## 控制入口

- application使用ProfileSpeedControl.for_driving，拒绝LEGACY和PURE_PURSUIT配置。旧配置不会静默恢复旧控制。
- SteeringControl的DWPP分支不再下落至target_command。代码明确注释关闭此入口；无有效几何/支持时返回主动寻路，不使用另一套巡线轮速律。
- 横道候选/接近阶段不再禁止主动寻路；只有实际停车停留、配置/任务故障才可拦截。避免目标看似有效而规划器拒绝后卡在TASK_WAIT。
- 横道unified_control启用后，旧PWM积分调速器不可达。横道提供物理速度上限和停车状态；最终STOP、礼让停留和通信监督仍可强制零输出。
- 基线算法留在库内供明确的离线比较/历史回归使用，运行程序不能通过配置选择它。

## 缺测与转向

DWPP保持同一动态窗口。测速不可靠时，不拿估计速度做积分误差反馈；近期实际发送指令的参考状态用于窗口，缺少近期命令或长控制间隔则重建小窗口。此时参考速度上限为正常上限的25%（当前0.075m/s），采用有界前馈。

这是参考速度和命令状态，并非实际测速保证，也不用于移动历史道路或横道位置。真实观测恢复后再启用速度反馈。正常0.30m/s上限、加速度、转向增益、UNO ±255范围均不提高。

超出前进轮速几何可达范围的追踪曲率投影到可达边界，并记录FORWARD_CURVATURE_PROJECTION，避免静止急弯时仅选择零速交点、永久不动。实际选中弧线仍接受车身余量检查。

## 横道生命周期

- 确认后：APPROACH，保留未完成停车义务。
- 位置/测速不足：RECOVERY_APPROACH，低速接近或主动寻路，仍需停车，不等同于通过。
- 重新定位：返回正常APPROACH；已确认条纹使用自己的几何方向寻找同一模板，不因中线信心低而直接禁止重定位。低信心场景不能凭空建立新横道。
- 无法恢复精确位置：保留名义位置，按名义距离和刹车需要执行一次停车。误差仍如实保留，不声称停位合规。不会仅因误差范围变大就在40cm外永久等待，也不会取消整个停车义务。
- 停留：正常物理静止、红灯和停距证据保留；证据缺失时使用已有的3.2秒停车ACK兜底，不无限等待。
- 完成停留：才允许RECOVERY_PASSING；无精确证据不计为已验证合规。连续实测证明未离开刚停车位置时，避免同一事件重复停留；失去位置联系后，新确认横道不能继承旧通过状态。

## 验证与限制

- 1,063项回归通过，包括连续缺测、噪声位移、急弯静止起步、任务零速不可被历史路径慢行下限覆盖、旧转向入口调用即失败、零速清除残留积分输出、横道缺测后的接近/停留/释放，以及低信心条纹重定位。
- 原始运行日志74个有效路径状态的独立规划探针：旧控制12个选择DWPP，57个被TASK_OWNS_SPEED关闭，4个因测速不明确退出，1个因其他门限退出；新版74个均选择DWPP。
- 该探针使用已记录路径/速度/误差，并为横道样本施加0.08m/s测试约束。不是逐帧图像重放，更不是闭环轨迹仿真，不能由此推导实车圈速、压线率或停距。
- 本轮不自动START/ARM。实体首次弯道的摆动和横道停距需在部署后实测确认。
- 计圈继续关闭，实测仍需手动STOP。
