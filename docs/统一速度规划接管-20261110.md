# v0.6.90：统一速度规划接管测试版

已验证的38秒版本保留为GitHub标签 `baseline-v0.6.89`，对应提交 `2b4bbc1`。该轮横道第一次刹停后模型距离约10.75cm，合法停留3.235秒后自动通过。用户要求今天完成代码和部署，实车对比留到2026-11-11；本记录不提供尚未测得的新圈速。

## 实际接管范围

`ProfileSpeedControl`接入`SteeringControl`，在正常、稳定、当前观测的道路上输出轮速建议，替代原来的巡航档位、置信度乘系数及弯曲负载调速。建议继续经过`DrivingSession`、任务限制、PWM爬升、峰值补偿、电机租约和UNO看门狗；规划器不能直接操作电机。

接管需要当前道路和选中的前瞻点已经确认、实测车身速度有效、原有车身包络检查可行、已有道路连续性确认达到响应窗口。前进位移还必须超过两倍运动估计误差；起步和无法可靠分辨的低速沿用基线，避免把零速附近的噪声用于速度反馈。预测、待交接、无有效光流、车身检查不通过或缺少路径误差时，保留基线控制作为回退。只有前进轮速模型可行时才使用新方案，短路段或不可行尖弯不会继承上一帧成功结果。

横道出现后直到完成停留，接近和停车速度继续由v0.6.89任务逻辑拥有，禁止两套速度积分器互相竞争。横道通过后恢复新规划。计圈、最终40cm、发车许可、STOP和失路恢复继续持有原有优先级。本轮没有将所有任务合成一个完整轨迹优化器，也没有移除已有保护。

## 路径、速度与反馈

与离线及SHADOW共用`plan_speed_profile`：曲率、外侧轮上限、可用支持路程构成点速度上限，向后保证制动，向前约束加速，反应延迟只计一次。输入使用命令时刻经实测运动补偿后的路径。

在线控制逐帧采用该段入口上限，时间方向的加速由参考速度爬升负责；不把整段离线速度表当作已经执行的轨迹。

`supported_path`统一提供连续观测段选择。在线控制已有独立的前瞻和车身许可，可以从历史前缀之后的第一处当前观测开始，但不给跳过的前缀任何额外制动距离，也不连接段内断口。段入口速度上限保守地用作当前车速上限；路径许可仍由巡线负责。距离余量扣除车头长度和两倍路径误差。

接管参数为速度上限0.30m/s、横向加速度0.15m/s²、前进加速度0.30m/s²；制动能力0.20m/s²和命令延迟0.35秒沿用已部署横道模型。最大实际UNO输出仍为200。加速度、横向能力、轮距比例及速度反馈增益尚未完成独立赛道标定，因此该版本为接管测试版。

目标速度通过实测车身速度反馈调节共同轮速幅值，保留原有转向曲率比例。反馈基于任务及爬升之后真正发布的逻辑轮速，避免对未发送的高轮速积累积分；实际零输出清除加速参考。低速和转弯没有把木地板90–200档位表外推成虚构电机标定。目标上升按加速度限制，目标下降立即生效，过速时进一步降低幅值。实际车速仍有响应滞后，超速及限制原因会记录，不能把规划上限当作瞬间可实现速度。

## 核对与回退

查看`steering.speed_profile_control`：`mode=ACTIVE`说明已接入，`selected=true`说明本帧实际选用新控制建议；`target_speed_m_s`、`ceiling_m_s`、`measured_speed_m_s`、`requested_wheels`分别表示目标、上限、实测及建议轮速。任务或道路回退时记录原因，例如`TASK_OWNS_SPEED`。最终电机输出仍以实际/逻辑PWM和UNO回执为准。

原`speed_profile_shadow`保持只读对照，仍明确`controls_motor=false`，不能用它判断接管是否启用。将运行配置的`speed_profile.mode`改为`LEGACY`并重新部署，可以在新源码中使用基线调速；需要完整回退时按标签`baseline-v0.6.89`构建部署。相机标定、ESP32固件和UNO固件本次不调整。

未ARM待机时完整CONTROL日志改为30秒一次，避免留机到次日仍持续写入大量重复数据；ARM等灯及行驶时保留0.5秒周期与原有事件日志。进入等灯、实际运行或STOP时即时记录，预览、触屏和控制帧仍逐帧更新。

新增回归覆盖未来弯道提前限速、盲区不给路程信用、观测断口、无光流及任务回退、真实发布轮速反馈与零输出复位、曲率比例与实际PWM上限、带相机延迟和电机死区的速度闭环、完整巡线选择新控制、未分辨起步回退以及横道零输出优先。待机日志回归同时确认预览和控制仍逐帧更新，ARM/STOP不等待30秒日志周期。899项Python完整回归全部通过，网页JavaScript回归通过。
