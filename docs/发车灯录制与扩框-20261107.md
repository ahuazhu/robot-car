# 发车灯录制与扩框（2026-11-07）

> 此文记录历史版本；现行许可锁存与阈值见[出发许可锁存](出发许可锁存-20261107.md)。
本次录制为ESP32传感器独立会话，Maix保持STOP、未ARM、输出零。用户保持亮灯，然后完成关灯再开灯。未向UNO发送行驶指令。

## 原始记录

`.maixpy/lamp-recordings/lamp-trial-20261107-a/`：90.21秒，405张320×240缓存JPEG、773条检测状态。`recording.mp4`供观看，`frames/`、`events.jsonl`和`markers.json`供分析。未记录配对密钥和会话nonce。JPEG是压缩后的原图，状态请求与图像请求各自带时刻，不能当作完全对应的原始RGB565帧。

真实状态772次WAIT_TARGET、1次LOCK_TARGET，没有一次锁定基线或确认熄灯。因此这次失败发生在灯面定位阶段，不能归为亮灭差值不足；画面中心亮度从约249降到约83，亮灭变化明显。

对JPEG重新量化后用同一C++预处理回放：旧96×84框内的亮区连到左右边缘，第一帧候选占约65%，同时被触边和超过半框面积规则排除。JPEG回放存在压缩误差，但与实机始终找不到灯面的状态一致。

## 按用户要求扩框

新框128×112，原图坐标`[96,8,128,112]`，中心仍为`(160,64)`。固件处理区域、Maix协议校验、两个设备预览和主机备用预览同步修改。原熄灯门槛、4帧/600ms确认、背景结构检查和通信时效未放宽。

扩大框的回放已能锁定灯面，但本段仍没有确认熄灯，不能报作已成功识别出发。附加的亮度补偿实验也没有通过本段，未部署实验修改。新固件增加rejection_reason、background_change、background_residual、darkened_fraction、required_drop遥测，供下一轮明确定位拦截原因。

当前发布目标：Maix0.6.65、ESP32 0.4.3-larger-roi；以设备实查为准。新框回归含新增区域、中心保持和历史未切灯负样本；全量642项通过。真实灯灭确认仍需进一步验证。

上线核对已通过：Maix0.6.65与ESP320.4.3均报告同一检测框`[96,8,128,112]`，中心`[160,64]`；两路JPEG正常，Maix未ARM、输出零，自恢复看门狗正常。最终记录见`.maixpy/esp32-larger-roi-20261107/validation.json`。
