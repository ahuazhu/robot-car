# ESP32 灯面像素分割与回测（2026-11-07）

> 此文记录历史版本；现行许可锁存与阈值见[出发许可锁存](出发许可锁存-20261107.md)。
固件：`0.4.4-lamp-mask`。Maix 保持 `0.6.65`，UNO 无改动。青框 `[96,8,128,112]`、中心 `(160,64)` 保持不变。

## 检测分层

1. **定位**：在青框内进行多亮度阈值连通域搜索，同时使用低饱和度分支及六个可重叠色相分支。白灯、过曝白色核心可走纯亮度路径，不固定比赛灯色。形状、边界、局部对比度和候选歧义检查保留。
2. **分割**：保存选中连通域的实际像素，腐蚀一层以避开光晕。掩膜保留孔洞，不再填充整个内接矩形。颜色类别每帧预计算一次，阈值搜索只查询位图。
3. **锁定**：至少4帧、300ms稳定亮灯后冻结掩膜和亮度基准。熄灯后沿用同一掩膜，不因灯不再明亮而重新找目标。黄色预览框仍表示灯面外包矩形，不表示框内每个像素均参与检测。
4. **曝光参考**：使用灯面和光晕以外的背景，分别估计共同亮度偏移与比例；背景有足够亮度层次时增加稳健的比例加偏移拟合。只有灯面本身变暗、且经补偿仍变暗，才累计熄灯证据。背景亮度变化不再直接否决；背景结构和周围新出现的大块亮物仍会中断确认。
5. **确认与通信**：保留至少70%灯面像素变暗、最少4帧且600ms、最大750ms帧间隔、2秒许可窗口。配对、会话、重启编号、STOP取消、单次消费和Maix道路就绪检查均保留。

分析画面为64×56，每个掩膜单元对应原始相机2×2像素。`/status.signal` 增加 `segmentation`、`mask_pixels`、`exposure_gain`；不会把掩膜图像持续放进状态消息，避免增加图传流量。

## 验证与限制

- 全部649项回归测试通过。新增覆盖多种灯色、与高亮横梁相连的彩色灯、非发光孔洞、冻结掩膜、背景单独变亮、有可观测背景的曝光变化及黑色龙门架背景。
- 固件编译成功；仅更新app0，保留原分区表、Wi-Fi和配对信息。烧录哈希、前版镜像和SHA256在 `.maixpy/esp32-lamp-mask-20261107/flash-record.json`。
- 实机只ARM过ESP32传感器来检查处理时延；Maix全程STOP、未ARM、电机输出0。实机短测搜索阶段中位耗时由38.978ms降为29.484ms、最大34.947ms；当前画面下2.4秒内相机序号推进20。通信和JPEG检查结果在同目录 `hardware-processing.json`，未进行实际发车测试。
- **仍有已知不可辨识情况**：纯色背景缺少多个参考亮度，不能同时确定全局增益与偏移。合成的均匀背景加“增益0.65、偏移20”会被误当成灯暗；当前只拒绝可观察和已覆盖的曝光干扰，不能承诺消除全部曝光误判。完全遮住灯或移走灯，也可能与熄灯相同。正式使用仍需固定相机、避免遮挡并用现场灯验证。
- JPEG回放存在压缩、缓存和时间采样误差。659ms是回放候选到确认的跨度，不是实测物理灯灭到小车启动延迟，也不能替代现场测试。
- 当前ESP32→Maix发车许可仍经车内Wi-Fi；此改动没有实现硬线UNO门控。
