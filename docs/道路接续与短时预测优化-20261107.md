# 道路接续、短时预测与计算优化（2026-11-07）

巡线优化已部署为Maix v0.6.71；随后v0.6.72沿用相同巡线逻辑，增加ESP32定位框尺寸兼容。v0.6.71部署后核对11个关键文件哈希、5个不同实时帧、UNO未ARM零输出及出发许可false。没有发出行驶指令，尚未做本版整圈对照。

## 道路接续

原代码仅在仍有有效片段时剔除过期部分；完全过期时，旧路径继续参与关联，会把清晰的新道路判为冲突。现在在感知和关联之前统一退休过期几何，只保留失效时的诊断值，且同一帧只做一次剔除。新道路独立连续确认，不再被过期几何否决；未确认候选不能供驾驶使用。

若本帧所选路沿具有跨帧确认的身份，可复用这个证据，避免连续可见道路刚越过5cm历史上限便增加一次停车确认。双边候选只有一边确认时，必须是可靠边沿，且融合中线在双方观测误差内与该边沿推算中线一致，不能借其它候选的身份放行。匹配仍检查实际重叠片段的位置、方向和顺序，没有全局放宽距离或转角门槛。

共享`RoadPolicy.confirmed_reacquisition()`用于视觉扫视与停车监督层。已经运行的任务在道路重新确认后直接交还巡线，避免再次累计初次启动的5帧；初次启动门槛、低质量、待确认、过时及未观测结果保留检查。

## 短时预测

普通遮挡与待接续道路使用同一可信预算：剩余盲行距离、支持长度、观测年龄、运动误差，并扣除处理期间按实测速率估计的行驶距离。预算接近耗尽时等比例降低两轮指令，保持转向比例；没有有效前进运动或预算耗尽时给零。预测只使用运动补偿后的已见道路，不生成新道路。

两种预测都发布不超过150ms且受剩余距离/时间约束的命令租约，普通遮挡不再只依赖通用UART心跳。5cm盲行、0.6秒历史上限、300ms命令过期归零、600ms失效及UNO看门狗未放宽。

车身未来轨迹现在使用与实际输出一致的转向增益和trim。原预测循环在第一次前进之前就用单位增益覆盖传入曲率，导致低增益时高估跟随弯道的能力；新增近零增益圆弯、trim及左右对称性回归。

## 计算优化与实测

光流仅复用上一帧成功测量的角点；点数不足、估计失败或帧间隔失效后重新检测。每帧仍执行双向光流、当前灰白路面范围、特征跨度、RANSAC和残差检查。灰白掩码用OpenCV整块运算代替多个NumPy中间数组，逐像素阈值不变。计圈白线的候选采样及亮度轮廓批处理，像素坐标、候选顺序及所有判据保持等价。

在Maix上用8种带配套标定的静态场景，以旧、新、新、旧顺序运行；每个版本48个计时样本，排除每场景最初两帧热身。两版本计圈条纹及横道条数一致。

| 阶段 | 优化前中位耗时 | 优化后中位耗时 |
| --- | --- | --- |
| 光流 | 29.95ms | 20.20ms |
| 视觉关键计算总计 | 118.34ms | 109.39ms |
| 总计90分位 | 134.19ms | 126.01ms |

关键计算总计中位下降约7.6%。同批新版样本按算术平均拆分如下（合计110.0ms，和109.39ms中位数属于不同统计量）：

| 阶段 | 平均耗时 |
| --- | --- |
| 光流运动估计 | 19.7ms |
| 白边/中线提取、道路模型、关联与选点 | 51.8ms |
| 计圈线检测 | 15.9ms |
| 横道检测 | 11.9ms |
| 转向与车身边界检查 | 10.7ms |

统计不包括摄像头采集、画面叠加、屏幕显示、JPEG编码和网络传输，也不是整圈圈速。第一版仅批量计圈采样未降低整体耗时，最终收益主要来自角点复用与重复计算减少，不能把所有收益都归到批处理。

后续优先剖析51.8ms道路处理中的重复拟合、几何构造和数组分配；再做计圈/横道的候选快速预筛。需要跳过完整检测的优化应先证明不会漏掉计圈线或横道；不通过提高超时或盲行上限掩盖卡顿。
