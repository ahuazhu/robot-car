# 代码评审与性能优化（2026-11-09）

本轮覆盖 Maix 道路识别、运动/转向、任务会话、预览，ESP32 发车及 Android 原型。源码版 Maix 0.6.78；未部署到车辆，也未启动电机。此前未提交的模型定位、手工框灯和灭→亮→灭发车逻辑一并审查保留。

## 最有影响的行车问题

旧 `CommandRamp` 在转弯恢复直线时按每个轮子限制升幅，然后对两轮一起缩放。内轮需要提速时，已经高速的外轮也被迫减速；连续小幅左右修正还会反复损失油门。

- 从稳定 `(80,163)` 到目标 `(163,163)`、命令间隔 100ms：旧序列 `(98,98) → (116,116) → (134,134) → (152,152) → (163,163)`；新序列约 `(140,140) → (157,157) → (163,163)`，恢复时间从 0.5s 降到 0.3s。
- 交替请求 `(120,163)` / `(163,120)`：两种指令平均、峰值努力相同，旧输出峰值可逐步降到 76，新输出保持请求努力。
- 新约束仍按已有 180 PWM/s 限制平均与峰值努力，保持请求两轮比例；精确零、STOP、过时命令重启仍优先。直行进入弯道的对照序列相同。

这是消除无意减速，不是实测最高车速提高。单轮瞬态加速约束已改为整车驱动努力约束，需在赛道确认出弯响应与是否出现摆动；没有编码器，PWM 不等于车速。最大输出仍为 200/255，弯道、弱观测、失路、横道和最终停车约束保留。

## 重复计算清单

| 路径 | 原行为 | 修改后 |
| --- | --- | --- |
| Maix 光度与颜色 | 多轮 NumPy 逐像素运算建立亮度与区域掩膜 | `perception.photometry` 负责光度分类，可选 C 核融合遍历；无新核时自动回退原 NumPy 数值路径 |
| 视觉静态参数 | 每帧建立膨胀核、采样窗口和部分长度界限 | 在标定/对象初始化时建立 |
| 转向轮速律 | 最多计算基准、局部质量、提速三套临时轮速 | 先确定最终质量和努力，再调用一次轮速律；共享路径弧长，删去重复运动计算 |
| 叠加路径投影 | 每个预测虚线段重新齐次投影 | 整条路径投影一次；80点全历史路径含两边界及目标时由43次降到4次 |
| 叠加逆矩阵 | 每次绘图求标定逆矩阵 | 应用初始化一次；只显示屏幕时不再缩放鸟瞰图 |
| 预览图像复制 | 原图复制一次，合成三图后发送再复制一次 | 原图直接参与新数组合成，合成数组向后台编码器转移所有权；每次发布少复制921,600字节，10Hz时约8.8MiB/s |
| 任务状态整理 | readiness、HTTP、日志及绘图各自调用任务快照，每帧2–4次 | 会话处理ARM/STOP后采集一次，在同帧各输出之间复用 |
| HTTP 性能信息 | 发布字典后继续补字段，HTTP可能读到半帧或与写入竞争 | `/vision` 在整帧结束后一次替换；`/status` 保持控制发布时的快照 |
| ESP32 灯面 | 锁定后继续计算只供找灯使用的颜色特征；重复曝光统计和固定几何掩膜 | 根据阶段计算颜色，合并曝光统计，缓存固定手调框几何；不改变判定阈值与时序 |
| USB配对/无线配置 | 两个脚本分别只接受0.4.3/0.4.6，拒绝当前固件 | 共享已知兼容固件清单，仍拒绝向未知固件发送凭据 |
| Android 原型 | 固定ROI多次建立背景掩膜并扫描曝光 | 缓存背景几何，复用曝光统计；仍不属于正式整车链路 |

没有删除原生加速的 Python 数值回退、独立几何参考及诊断程序；它们仍有容错或验证用途。没有再加一套道路历史或发车状态，状态归属仍由各层现有组件负责。

## 本机基准与验证边界

Mac本机的耗时不能直接换算为Maix延迟或圈速，也不能将几个独立阶段的收益重复相加。

- 道路识别：85张历史帧逐值等价；正式基准使用这85帧及4张弯道/阴影/反光样本，交错7轮，预处理中位1.356ms → 0.812ms（下降40%），完整道路识别中位2.538ms → 2.061ms（下降19%），P95 4.654ms → 3.980ms。87帧只需一档阈值，因此没有另加跨阈值缓存。
- 绘图：80点全历史路径、两边界和目标，预热20次后500次，中位3.056ms → 1.187ms；100组随机混合观测掩码下原图/鸟瞰输出逐像素相同。该构造偏重历史虚线，不代表典型整帧耗时。
- 转向：8种道路场景最终命令新旧相同；成熟直道轮速律2次 → 1次，局部质量场景3次 → 1次。局部耗时约2.24ms → 2.06ms、2.43ms → 2.26ms，噪声较大，以计算次数和控制序列作为确定证据。
- 部署前设备只读抽样：0.6.77、停车且当前无有效道路，控制链约49ms，其中运动19.8ms、道路27.5ms；这不是赛道基准。光流保留正反向一致性与质量检查，本轮没有为提高数字而跳帧或删除检查。

- ESP32检测内核：直接C++交替11轮、每轮700帧，手工等待亮灯297µs → 256µs，锁定后328µs → 293µs，自动定位668µs → 621µs；约7%–14%，仅为本机结果，模型推理速度未变。

道路基准复现：

```sh

  CURVE_NATIVE_LIBRARY=/tmp/robot-review-kernel.so \
  .maixpy/.venv/bin/python maixcam2/curve_follow/tools/benchmark_perception.py --repeat 7
```

## 验证结果

- 完整原生核测试：746项通过；覆盖STOP优先、瞬时/过时命令、转向/失路、横道停留、计圈、终点停车、HTTP并发和打包回滚。
- 完整Python回退测试：746项中723项通过、23项原生专用检查按设计跳过。
- 新光度核：随机阈值边界、非二值掩膜、反向/非连续视图及85帧逐像素/道路几何等价；真实旧.so缺新符号时回退测试通过。
- ESP32：对冻结0.4.12逐帧对照112组、3,086帧，公开状态、诊断和灯面掩膜完全一致；覆盖灭→亮→灭、白/红/绿、重新ARM、断帧、曝光及时间回绕。
- Android：48组、2,160帧与旧原型等价，Java检查和APK离线构建通过。它仍是独立本机ON→OFF原型，没有UNO/Maix通信，不属于正式整车时序。
- UNO：原生C++驱动/看门狗检查通过，含两次模拟2小时会话；固件未改。
- Maix应用包及安装器构建通过；新C符号已纳入安装核验。ESP32 0.4.13固件编译通过，Flash 1,711,053字节、全局RAM 132,780字节；没有刷机。
- 入库保留模型权重与Gradle wrapper；私有密码、配对密钥、本机配置、图片/录像和构建产物不入库。模型导出仍需说明中指定的本地实物诊断参考图，不以合成亮灯图代替。
