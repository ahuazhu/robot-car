# v0.6.108：运行状态序列化修复

v0.6.107实车运行约50帧后，设备记录两处相同异常：网页/status响应和application.py的CONTROL日志json.dumps均报`TypeError: Object of type bool is not JSON serializable`。主循环按异常退出，日志存在FINAL_STOP_ACK，随后网页8000端口拒绝连接。

本地已复现：车身余量上限为NumPy float64时，speed_profile.initial_overspeed比较结果为NumPy bool，而非Python bool。速度规划早已接受这些数值，但v0.6.107扩大DWPP覆盖范围，让此前回退旧轮速算法的场景也生成此状态。这是本次上线暴露的回归，之前回归未覆盖NumPy输入下的完整JSON输出链路。

修复分两层：

1. 生产者明确将initial_overspeed转换为Python bool，普通json.dumps也能正常编码速度规划状态。
2. 日志与HTTP输出共同使用数值JSON编码器，仅将NumPy布尔/整数/浮点/数值数组转换为对应原生值，不转字符串、不默默吞掉未知对象、不改变控制计算。

新增回归使用连续15个真实规划状态、NumPy输入和实际HTTP服务，逐次检查CONTROL等价编码、/status、/vision。还覆盖数值类型保持及未知类型拒绝。现场失败日志在`.maixpy/runtime-error-20261111/`。

本版不调整行驶参数、横道规则或UNO固件。

验证：1,065项回归通过；Maix板端12次真实HTTP类型检查通过，在线帧号488→490，两个状态接口均正常。25个关键文件哈希一致，v0.6.108已部署，最终核验时未启动。部署记录：`.maixpy/runs/20261111-183937-install_curve_follow_drive/`。核验期间操作者曾短暂运行；只读测试不应假定操作者无法START/STOP，因此板端接口检查只断言版本/接口/帧推进，并记录真实启动状态，不发控制请求。
