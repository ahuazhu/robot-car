# 发车灯持续待确认修复

## 现场根因

Maix 0.6.83 / ESP32 0.4.14 的实机状态记录显示：熄灯后 `TARGET_UNCERTAIN`、`LAMP_NOT_DARK_ENOUGH` 持续，灯面变暗像素比例 100%，背景残差约 2–3，ESP 通信正常。亮灯采集得到 `noise=43.2`，据此生成 `required_drop=129.6`。

原实现把亮灯采集序列的最大值减最小值作为 noise，随后按标准差的用法乘三。起灯和自动曝光收敛期间的正常变化会把这个门槛过度抬高；基准锁定后门槛不更新，因而等待更久也无法恢复。此前偶发成功只代表某次亮灯采样较平稳，不能证明该问题不存在。

## 修复

ESP32 0.4.15-lamp-noise 用 Welford 方法计算采集序列均值的总体标准差，熄灯门槛继续使用 3 倍标准差。手动与自动定位共用采集统计，仍保留原有峰峰值稳定门；最终被保存的参考帧还必须处于均值附近，避免最后一帧亮闪导致恢复正常亮度被误认成熄灯。该修复没有额外增加亮灯采集时长，也没有移除背景曝光补偿。

仍要求先观察 OFF→ON，亮灯至少 4 帧且 300ms；熄灯至少 60% 灯面像素有效变暗，并持续至少 3 帧且 400ms；背景结构改变不授予出发许可。Maix 出发许可锁存及巡线、电机检查保持原逻辑。

## 验证与部署

新增 8 项实际 C++ 回归通过，另有 149 项相关原有测试通过。最小同输入回放中，旧版采样范围 49 被当作噪声，门槛 147，正常熄灯持续 21 秒仍拒绝；修正版标准差 20.53、门槛 61.59，在第 3 帧、420ms 确认。新增负例涵盖持续亮灯、曝光变暗、背景结构变化、瞬间熄灯、采集末帧亮闪及重新采样。
