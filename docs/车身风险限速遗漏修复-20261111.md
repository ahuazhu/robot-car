# 弯道转向不足与车身风险限速（v0.6.100）

用户反馈v0.6.99压线较多、转向稍有不足。只读抓取时小车仍在运行，未发送STOP或启动命令。原始日志与当时预览在本机`.maixpy/line-crossing-20261111/`。

## 已确认的遗漏

390份运行状态中，161份由统一速度反馈接管。3份接管状态的速度参考高于同帧车身预测所隐含的限速。例如帧1849：车身预测约10cm后可能触边，对应约0.142m/s限速，规划参考却为0.202m/s。

车身预测原本只输出`safe_speed / current_speed`比例。当前速度较低时该比例被截成1，速度规划器因此认为可以加速，但没有收到仍应有效的绝对上限。超出后又退回旧轮速控制，容易反复加减速。中线识别置信度高不代表当前车速和车身转弯轨迹有足够路沿余量。

这是可从日志和代码确认的限制遗漏，尚不能把所有现场压线都归因于它。日志中的实际转向还包含运动估计及电机响应延迟，现有稀疏状态不足以重新标定转向增益。

## 修正

- 车身预测同时提供`speed_limit_m_s`绝对限速，与置信度、曲率、外侧轮速度和可用路径制动约束一起取最小值，限制参考速度及继续加速。
- 车身风险减速时仍可使用正常速度反馈，不因旧比例小于1就退回基线控制。
- 测速缺失时，轮速幅值受置信度和车身绝对限速共同约束；旧相对比例不再重复相乘。新旧线接续需要同时满足两条路线的较小车身限速。
- 完赛优先模式下已经触边时保留与原置信度模型一致的0.03m/s慢行参考；不新增长时间停车等待。STOP、正常横道礼让、完赛和通信时效仍优先。
- 最高速度0.30m/s、直道轮速、转向增益0.85及原标定沿用原配置。改善目标是在转弯余量不足时给现有转向响应更多时间，而不是全程降低直道速度。

## 验证

现场帧1849、2027分别验证左右转向的原参考超限情况，新规划参考都不得超过对应车身限速。回归同时覆盖低速重新加速、测速失效、共享接续限制、已触边慢行及真实STOP权限；无车身风险时的规划结果保持原约束。

构建和数值回归不等同于实际压线率下降，仍需同一段赛道复测。部署仅在小车未ARM且零输出时进行，不自动发车。

完整回归996项，992通过、4项跳过；随后补充的双路线限速测试与速度反馈组22项通过。v0.6.100已在用户STOP后部署，记录`.maixpy/runs/20261111-140702-install_curve_follow_drive/`；安装器确认启动时未ARM，原标定和运行配置不变。17份关键文件哈希匹配，UNO无错误、ESP32在线。

部署后用户已重新启动小车，因此额外板上数值探针在检查到任务运行后主动退出，没有执行重负载回放或发送控制指令。只读在线快照已观察到`BODY_CLEARANCE`接管：约0.773中线置信度允许0.290m/s，但同帧车身风险将最终规划上限压至0.142m/s；这是实际控制约束生效的证据，不代表实车压线率已验证。

复核更正：最初本地统计把平顺减速0.08m/s²误用于车身刹停限速计算，导致数量和示例上限有误。实际SteeringControl使用0.20m/s²，故该批记录中明确超限是3份、示例上限约0.142m/s。设备修复始终直接复用实际车身预测值，不使用错误的本地统计常量；对应历史测试已改为读取同版配置依据。
