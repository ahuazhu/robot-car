# 短暂漏检接续与提速（v0.6.93）

用户报告同赛段41秒，本轮重点减少短停及重新加速。拟合负责把已见道路变成平滑曲线；真正跨越漏检的是带运动补偿、时间及行程预算的历史中线。正常短暂漏检应保持可用的行驶输出，不能只因新候选尚待确认就停车。

## 记录中的限制

下载日志包含两次启动。首段完整活动记录约47秒，不能把其中每一秒都归入用户手计的41秒；末端约40秒后出现真正道路支持消失，可能已离开计时赛段。明确的短暂停车发生在约17.2秒、25.8秒、27.5秒、28.8秒、31.0秒附近，部分源于光流失败，部分在旧曲线仍有效时等待新候选确认。

首段实际选用速度规划的25个采样点中，速度上限中位数约0.220m/s，实测速度中位数约0.181m/s。将横向加速度从0.15放宽至0.20m/s²重新计算这25段，速度上限没有变化：主要约束是外侧车轮和前方支持范围。本次保留横向加速度与最高速度。

原历史行程预算只有5cm，计算延迟所消耗的行程也须扣除；在约0.2m/s、单帧约0.17秒的运行条件下，一次漏检加处理延迟已可能耗尽预算。前进预测租约原来最多150ms，也短于常见相邻控制帧间隔。放宽数值之外，还必须修复候选确认对历史路径的额外否决。

## 接续行为

- 完赛优先模式下，新候选仍独立多帧确认。只要旧中线存在且通过原有支持、车身及误差检查，就先沿旧曲线行驶；候选不会因为这次接续被当成已观测、已接受的道路。准备发车仍要求当前可靠道路。
- 单帧光流失败时，最多用最近一次实测SE(2)运动的恒定速度预测0.25秒，误差随时间增长。预测保留`valid=false`，另标`prediction_valid=true`及来源，不能更新最近实测时间或给自己续期；相机帧缺失直接清除此预测。
- 预测运动只用于短时位置补偿与受限接续，不能进入高速闭环、自学习转向修正、横道实际停车证明或计圈实测里程。
- 当前运行配置允许最多15cm历史行程，历史时间仍最多0.6秒，并继续受道路质量衰减、位置误差、剩余支持长度和当前绿色反证限制。更早耗尽任一预算仍停止使用旧曲线。
- 前进预测指令最长0.25秒，实际租约取剩余时间与距离可支撑时长的最小值；原地反转轮速的探路租约仍最多0.15秒，实际视觉探路仍为0.12秒。独立电机进程300ms清零、600ms解除驱动的保护不变。
- 看不见路持续超过接续能力后，进入v0.6.92的反复短促寻路；STOP、最终完赛与横道规定停车优先。

## 加速与计算

`motor_rise_pwm_s`从180调整为240，使冷启动和短停后更快恢复原目标努力。`speed_profile.acceleration_m_s2`从0.30调整为0.40，使速度参考更快追上已经计算出的速度上限。二者不改变停车指令的立即清零、外侧车轮约束、PWM200峰值、0.30m/s速度上限或横道3.2秒要求。

ACTIVE控制接管后，旧SHADOW对照已不影响行车，停止它的逐帧重复几何与规划运算。输出保留字段，但明确标成`mode=DISABLED`、`valid=false`、`reason=ACTIVE_PROFILE_OWNS_SPEED`，不将旧成功结果伪装为当前结果。实际规划仍逐帧运行并记录。LEGACY与独立离线分析仍可使用原对照器。

## 验证边界

`test_short_dropout_continuity`覆盖每秒5帧时漏一帧仍前进并重新接回、预测不续期、刚体转弯变换、当前候选不覆盖旧路径、绿色反证及支持到期。`test_curve_motor_channel`验证前进租约超过150ms仍持续、到期后由子进程清零，旋转长租约仍拒绝。速度闭环仿真覆盖新旧加速设置、相机延迟与电机死区；它不是实车动力验收。横道及人工STOP继续由完整回归验证。

本轮收益要以同赛段再次实测为准，不能由速度上限或仿真推算一个已实现的圈速。实拍日志及临时回放在`.maixpy/speed-41s-20261111/`，不入Git。
