# ESP32定位框扩大（2026-11-07）

已部署ESP32 **0.4.6-larger-roi**，配套Maix **v0.6.72**；v0.6.71的道路接续与计算优化完整保留。

320×240原图中的定位框从`[96,8,128,112]`扩大到`[80,0,160,128]`，中心仍为`(160,64)`。宽度增加25%，面积增加约42.9%；上沿到画面顶部。网页青框与设备真实搜索范围同步，黄色框仍表示锁定灯面，确认时使用分割后的实际核心像素，不拿整个青框平均亮度发车。

扩大范围会引入新的背景候选。定位保留原128×112中心区域的优先级，扩展区用于补充定位；中心优先权固定于传感器像素尺度，不随搜索面积扩大而减弱。核心区域有合格灯面时，外围新增亮物不能取代它；核心区域无候选时，扩展区内的完整灯面仍可正常锁定。多个相近候选仍保持不确定，不放宽ON/OFF阈值。

Maix白名单同时接受旧、新两种ROI，锁定灯面的合法边界根据实际上报范围检查；展示使用设备元数据。固件ROI上报直接取自检测器常量。原生回放工具也从C++内核读取几何，掩膜缓冲区随之变为64×80，避免仍按旧56×64分配。

685项完整测试通过，覆盖新扩展区目标、外围亮物不替代中心目标、原始历史小灯亮→灭、外部变化不能触发、掩膜孔洞、许可锁存及几何越界。405帧完整ESP32录制回放仍能锁灯并确认熄灯，候选到确认449ms；17帧未切灯抖动无触发。JPEG回放不代表物理响应时延或实际赛道准确率。旧Maix镜头的短样本及整体平移构图仍保留不确定/上下文不足结果，没有用填充区域当作正样本，也没有把所有短样本都宣称通过。

刷机前确认原ESP32-S3硬件地址，设备旧app与本地0.4.5备份摘要匹配。只在app0的0x10000地址更新823984字节镜像，并校验设备摘要；未写NVS、bootloader、分区表或UNO。Wi-Fi及配对保留。Arduino会在构建副本添加#line，核验曾误把该元数据视为缓存差异；规范化后源码与已刷镜像一致，设备摘要复核通过，首轮写入实际已包含最终逻辑。干净重编译镜像另存，但未用它覆盖设备。

最终两端连续5次检查均上报ROI160×128且在线；ESP32配对为true，相机帧持续更新。Maix未启动、出发许可false，UNO未ARM且确认零输出。本轮没有按Maix ARM、没有发出非零电机指令，也未做真实信号灯摆放测试。当前相机朝向桌面，放回赛道并正确框住灯后再由用户ARM。

本机8123入口的跳转/设置服务已同步固件版本和USB端口，继续禁止重复主机视频拉取。当前USB串口`/dev/cu.usbserial-14140`只用于维护；无线运行可以用充电宝供电。

本地忽略目录`.maixpy/esp32-roi-160x128-20261107/`包含旧镜像、源文件备份、最终编译镜像、回测、设备摘要、发布核验和主机服务记录。`firmware/`是已写入并校验的镜像，`firmware-final/`是额外干净重编译的核验副本。Maix安装记录为`.maixpy/runs/20261107-125445-install_curve_follow_drive/`。
