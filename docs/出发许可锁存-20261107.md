# 出发许可锁存与信号阈值（2026-11-07）

当前实现：Maix `0.6.66`，ESP32 `0.4.5-latched-signal`。正式发车使用ARM；网页“手动测试启动”用于跳过等灯的调试。

## 许可归属与复位

出发许可由Maix保存，初始化为假。收到本次ARM会话中符合条件的ESP32熄灯确认后，立即锁存为真，随后不再因时间、ESP32离线、重启、相机失效或图传故障撤销。

| 情况 | Maix出发许可 | 行为 |
| --- | --- | --- |
| 程序初始化、尚未识别熄灯 | 假 | 不依靠信号灯自动发车 |
| 匹配本次会话的有效熄灯确认 | 真 | 等待道路、电机及本机画面条件就绪 |
| 等待道路超过两秒 | 保持真 | 道路就绪后可发车，无需再等灯 |
| 识别成功后ESP32离线、重启或崩溃 | 保持真 | 不影响本轮已获许可及运行 |
| 本机道路或电机故障停车 | 保持真 | 电机停车检查仍独立生效，不自动绕过故障 |
| 网页或触屏STOP | 假 | 清除许可，取消等待；下一轮重新识灯 |
| 完成目标圈数、车尾清线及收尾行驶后最终停车 | 假 | 本轮结束，不复用旧许可 |
| Maix应用重新初始化 | 假 | 不恢复旧许可，清理ESP32遗留会话 |

许可与“已运行”“是否正在等待灯”“ESP32当前在线”是独立状态。`StartSignal.consume()`只在本次ARM中使用一次许可，但不把许可值改为假；`started()`也不撤销许可。程序STOP先清本地许可，再请求UNO停车，因此UNO应答失败不会保留旧许可。

短暂通信失败发生在首次收到确认前时，Maix保持同一个ARM会话等待恢复，许可仍为假；会话变化、设备重启或错误确认数据不会产生许可。新鲜且匹配的确认一旦收到就锁存，不设置确认事件两秒有效期。

ESP32确认前仍有两秒通信租约；确认成功后保留该会话的确认结果，直到认证取消，不再因租约超时抹掉。Maix收到确认后立即请求取消ESP32检测；取消失败会重试。重新初始化或STOP时发现遗留ESP32会话，会认证取消旧会话，而不采纳旧的发车结果。

## 适度放宽检测

青框仍为 `[96,8,128,112]`，中心不变。灯色不固定，仍按亮度和颜色分割灯面，锁定后固定检测像素。

| 项目 | 原值 | 当前值 |
| --- | --- | --- |
| 亮灯基准 | 4帧、至少300ms | 保持 |
| 定位搜索起始亮度 | 区域中位亮度+18 | +12 |
| 定位局部对比度 | 18 | 14 |
| 熄灯亮度变化下限 | Lab L8的10 | 8 |
| 噪声倍数／基准对比度比例 | 4倍／12% | 3倍／10% |
| 需要变暗的灯面像素 | 70% | 60% |
| 熄灯确认 | 至少4帧且600ms | 至少3帧且400ms |
| Maix已获得的许可 | 两秒后失效 | 保持到STOP或最终停车 |

保留稳定亮灯在先、熄灯在后、曝光补偿、背景结构检查、帧新鲜度、会话和重启编号检查。放宽阈值意味着更偏向避免漏检，仍不能完全排除遮挡、移动灯面或复杂曝光造成的误判。

## 旧提示的根因

旧设备日志中保存了五次“SIGNAL_READY → INVALID_SIGNAL_RESPONSE → FAULT”：熄灯已确认，UNO在线，但道路目标无效、置信度0，等待发车时旧的两秒许可过期。旧代码把过期确认归为无效响应，显示成“信号中断”，随后又将确认计数清零。证据保存在本地忽略目录 `.maixpy/esp32-expiry-20261107/device-before-transitions.json`。

当前实现移除了许可过期分支；页面显示“出发许可已锁存”，即使ESP32后续离线也不覆盖这个结果。首次许可前的网络等待与真正会话故障分开显示，故障原因保留到下一次ARM或STOP。

## 验证与部署材料

- 663项回归测试通过，包括真实许可接收器与会话控制器联测：先获许可、等待道路30秒并模拟ESP32掉线后仍能启动；运行中掉线不影响电机发布；STOP和最终圈数停车清许可；UNO停车应答失败时本地许可仍清除；旧会话和无效确认不能发车。
- 同一固件C++内核回放此前405帧真实录像，首次熄灯候选46.997秒，47.446秒确认，跨度449ms。该数值是JPEG回放结果，不是实车启动延迟。
- 本次持续亮灯录像53帧，1.570秒锁定，没有熄灯误触发；17张历史路人／抖动图没有触发。样本数量有限，不能据此推算现场成功率。
- 部署、版本、哈希、回滚镜像和硬件检查保存在 `.maixpy/permission-latch-20261107/`。Maix安装器保留本机标定和配对配置；ESP32只更新app0，不覆盖Wi-Fi、NVS或分区表。
- 本次未自动启动小车。现场仍需验证实际灯光、道路和整车行驶。
