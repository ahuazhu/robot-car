# v0.6.88：横道远停与错误放行

正向多次在横道前约38–40cm停车，等待后直接通过。代码中确实存在两条相关路径：制动使用相机平移速度的模长；未验证合法停位的 `RECOVERY_HOLD` 也能在3.2秒后进入 `PASSING`。本版本修改这两处行为，替代此前允许“异常礼让后通行”的策略。

## 现场证据与边界

用户反向测得整车投影最近点18cm、最近车轮20cm；这两个参照不同，不相互矛盾。对应记录的模型停距17.265cm、误差2.25cm，状态为 `LEGAL/HOLD`。因此没有增加固定距离补偿，也没有修改相机标定。该轮为测量提前按STOP，不能视为完整停留验收。

正向记录中，帧11889在39.19cm进入 `STOPPING`，帧11895在38.50cm处为 `RECOVERY_HOLD/TOO_FAR`。另一轮帧13013在39.95cm进入 `STOPPING`。该帧场景平移速度模长0.38862m/s，车体前进速度约0.26550m/s，角速度约−0.58181rad/s。旧公式以0.38862m/s、0.35秒延迟及0.08m/s²制动参数计算约1.08m停车距离，足以触发远处停车。历史控制日志没有保留完整旋转矩阵和平移向量，不能把车体前进速度直接当作修复后的精确横道接近速度。

原始记录仅保留在 `.maixpy/speed-resume-0.6.87-20261110/`：`reverse-crosswalk-stop-full-rate.json`、`reverse-crosswalk-measurement.json`、`forward-far-stop-app-tail.log`。`forward-crosswalk-stop-full-rate.json`在该轮横道已开始通过后才启动采集，不用它推断此前刹停原因。

## 新行为

- 制动及横道速度反馈使用整车到横道的距离缩短速率。场景变换为旧坐标到当前坐标的 `R,t`，当前横道单位法线为 `n`，车身支撑距离为 `h`：`v = max(0, (-n·t + h(n) - h(Rᵀn)) / dt)`。横向平移不再全部计作接近；转弯时车角接近横道的部分仍保留。没有带时间的变换时，旧接口只可使用平移模长加车身旋转半径项的保守上界；无有效运动证据仍零输出。
- 接近期间位置或运动证据短暂失效，只暂停接近，不视为已完成停车；证据恢复后可继续正常接近。
- 已提前停车且整个误差区间仍在20cm外时，必须同时取得同一横道的当前精确匹配、道路就绪、实际停稳、零速回执和红灯证据，才恢复正常接近。早停的停留时钟清零，不能抵扣最终合法停留。
- 一旦取得合法停车证据，本次事件保持停车，不因随后距离波动反复挪位。边界模糊、陈旧或粗糙定位不会授权向前微调。
- 只有整车不压线、最近距离小于20cm的停位已验证，且连续停稳、零速回执、红灯满足3.2秒，才进入 `PASSING`。未知、过远、可能压线不会因等待超时自动放行。
- 快照新增实际接近速度、速度来源、场景速度模长、预计制动距离和感知暂停原因，方便下轮直接核对。停止后的叠加标记为 `PREVIEW`，感知暂停标记为 `WAIT POSITION` / `WAIT MOTION`；控制台不再把未验证停位显示为即将完成的3.2秒倒计时。
