# 横道出现后持续停车：状态切换修复（2026-11-07）

已修复并部署 Maix **v0.6.70**。本次持续停车来自搜路与横道任务的协调错误：横道接近阶段禁止原地扫视，但扫视状态机把这个限制也用于阻止已恢复的正常巡线。

## 现场证据

v0.6.69停车时，Maix仍处于active，ESP32发车许可为true且已成功消费，UNO仍ARM且持续确认零输出，串口无错误。实时处理约175ms，未超过280ms预算。道路已是有效OBSERVED、ONE LEFT，置信分数约0.81，当前道路目标与转向追踪点均存在；横道处于APPROACH，车身前方距离约0.32m，尚非横道停车等待阶段。

采集日志中有130个符合上述冲突的控制样本，首末覆盖76.82秒：均为`REACQUIRING ROAD`、零输出，搜路状态原因为`YIELD TASK CANCELLED VISUAL SCAN`。相机画面同时清楚显示单侧路沿与横道。此证据解释这次持续停车，不代表所有历史短停都来自同一原因。

## 根因与修复

`application.py`根据横道任务设置`search_allowed=False`，含义是禁止搜路旋转。尚未进入扫视时，`RoadSearch`会正常放行已有巡线命令，再由横道任务限速或停车。但是一旦进入`BoundedVisualScan`，它在`allowed=False`时每帧立即返回`_finish()`，后面的新道路确认逻辑完全无法执行；每次_finish还会清空恢复计数。车不动，横道仍在前方，禁扫视条件也一直存在，于是持续输出零。

修复将“取消搜路旋转”作为一次状态转换：取消后保持finished，禁止继续发出旋转脉冲，但允许新道路证据继续完成恢复。一般道路仍需5次连续合格观测；道路模型已确认的重新获取结果仍可复用其确认。弱、过时、未观测、待确认道路与车身边界阻挡均保留原有门槛。

巡线建议继续经过`DrivingSession`和`CrosswalkTask.limit_command`，横道接近限速，以及STOPPING/HOLD/RECOVERY_HOLD零输出仍由横道任务决定。此修改未改变信号灯出发许可锁存、标定矩阵、转向增益、速度、制动参数、马达看门狗或搜路脉冲上限。
