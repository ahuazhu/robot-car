# v0.6.104：横道后的路线置信度与控制交权

用户实测v0.6.103后反馈两圈横道前后处理不佳、最近一次发生掉头，并从预览指出转弯后弱中线仍会引出道路。
同时要求加强转向、小幅提高正常行驶速度。本机原始数据位于`.maixpy/dwpp-crosswalk-20261111/`。

## 可确认的原因

抓取到364份运行快照。几次已验证横道停车的模型停距约10.2、12.3、12.7cm，
实际连续停稳礼让约3.20、3.30、3.34秒。这些是模型距离，不是现场尺量。
最近一次问题出现在礼让结束并驶过横道之后，不能归因于礼让时间过长。

- 帧1447旧路线置信度约0.054；帧1448确认了方向变化约60度的新路线，重建模型却将
  `observation_agreement`直接置1，最终置信度立即跳至0.788。
  几何替换确认与恢复控制信心被混为一件事，削弱了速度规划在路线突变期间的降速作用。
- 随后实际已有可执行巡线指令，帧1452/1460置信度约0.77，但寻线模块检查的是
  `age_s`（所保留路线中最旧部分的年龄0.62/1.85秒），而不是最新接受观测的
  `road_model.model_age_s`（均为0）。因此没有及时交还巡线，并执行了多轮原地正反旋转。
  日志最后累计14次寻线脉冲。用户报告的完整掉头缺少同步外部录像，不能仅用脉冲计数推算实际旋转角。
- 速度反馈要求刹车时会产生合法零指令。历史跟踪曾将该零指令转换为“无巡线指令”，
  给寻线器留下错误接管机会。
- 横道接近阶段将“没有当前直接道路观测”视为“道路不可用”，会在有效历史路线仍可跟踪时
  反复切换APPROACH/RECOVERY_PASSING，增加接近过程的速度变化。

本次运行控制流水线中位数约149ms、完整循环约178ms。计算超时仅见一份快照，
这轮掉头主要涉及上述路线与交权逻辑；事件采样快照不是全程时间分布。

## 修正

1. 持久路线替换时保留已有创新不一致惩罚。新路线获得独立、连续、相容观测后，
   才按现有`confirmation_evidence`逐步恢复置信度；冲突立即降信心，单纯等时间或缺少观测不恢复。
   对已接受融合路线也保留观测创新的影响。历史几何仍不按时间/里程过期。
2. 最新接受观测的年龄与最旧历史尾段年龄分开使用。寻线结束和确认恢复使用已有
   `model_age_s`；无该字段时兼容旧记录。已有车体扫掠、有效路径、观测质量及控制时效条件保留。
3. 合法刹车零指令保留“道路控制指令”身份。基于有效置信度包络的零指令取消寻线，
   不被原地旋转替换。真正无路或不可执行目标仍按既有有界搜索处理。
4. 横道任务独立接收`road_available`，可用预测路线不再触发道路丢失恢复；真正道路丢失
   仍立即释放寻线权限。当前直接道路观测在停车证明中的原有用途保留。
   停车区间、红灯、3.2秒停稳礼让和禁止二次细调均保持。

## 小幅调参

| 参数 | v0.6.103 | v0.6.104 |
| --- | --- | --- |
| 统一转向增益 | 1.05 | 1.15 |
| 普通巡线基础PWM | 135 | 145 |
| 已确认道路PWM | 155 | 163 |
| 正常直道基础上限 | 163 | 163 |
| 最终峰值PWM | 200 | 200 |
| 参考速度上限 | 0.30m/s | 0.30m/s |

同一目标的请求曲率约增加9.5%，左右弯共用参数，车身预测也使用同一增益。
基础/确认档提高不撤销置信度、车身余量、曲率或任务限速；弱路线仍慢行。
数值增加不等同于实际轮速或圈速同比提高，效果需同段复测。
几何理想模型的最小车身余量也不保证随转向增益单调改善，回归检查实际扫掠及正余量。

计圈保持暂停，不按圈数自动停车；STOP、发车许可、通信时效及相机控制时效保持原逻辑。
