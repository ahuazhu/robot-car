# robot-car

miniAuto 麦克纳姆轮小车：MaixCAM2 视觉巡线，Arduino UNO 电机控制，ESP32-S3 摄像头预览及后续路牌识别。

## 当前版本

**v0.6.29-three-laps，2026-10-31**，分支 `experiment/speed-200`。本次将当天已部署的修正整理到同一版本：

新增龙门架发车灯：使用2026-10-31实拍亮/灭样本校准的灯芯与背景区域，兼容灯芯过曝为白色。应用打开后等待信号；连续及时画面确认亮灯至少0.35秒，并通过原有道路、UNO和横道任务启动检查后，自动发车一次。STOP取消等待并停车；网页ARM（触屏START）只重新等待灯光，不绕过发车灯。运行结束或故障后不会因灯仍亮自动重启。`runtime.json.start_light.enabled=false`恢复手动START。灯、镜头、起点位置改变时，需要重新采集发车灯亮/灭样本；这与地面道路标定分开。识别只在等待发车时执行。

本次还保留了已部署的AAA入口名称/顺序和2026-10-31道路标定；原v0.6.26基线在`.maixpy/baselines/before-red-light-start-20261031/`。本地实拍回放和时序测试通过；实车灯控触发验证结果单独记录在`.maixpy/red-light-start-20261031/`。

- 右偏修正：使用车身居中摆正的30/60厘米标定，横向光学偏置已吸收在投影中，不重复平移。
- 转向过度调整：转向增益0.85、弯道基础巡航120，直道163加既有补偿后最高200/255；寻路基础输出单独保持60。
- 弯道连续性：在实测运动和车身余量允许时，确认新观测期间短时沿可信旧中线继续；不刷新旧观测时间。暂停后的输出包络只在确认车辆仍滚动时保留。
- 横道漏检修复：原始亮度检测失败时，复用局部对比度图检测重复横条，保留尺寸、间距和多帧确认；遥测区分检测失败和事件关联失败。
- 横道事件切换：已完成礼让的旧横道失去可靠定位后，新出现且不匹配的前方横道独立确认，确认期间即限制接近速度。新事件需重新完成礼让；不把旧事件的通过许可沿用到新观测，也不把身份不确定冒充为已证明通过。
- 横道停车采用规则区间：整车投影不压线且小于20厘米。已停稳且误差区间合规即保持零速计时；不再向8厘米制动缓冲点挪动，区间内测距变化不重置连续礼让。3.3秒为工程等待值，原文要求超过3秒。
- 横道再接近只接受当前帧关联成功、且运动定位质量足够的观测。停车时保留的旧位置不能授权重新前进，防止过期横道在接近/停车间循环、起步输出被不断重置。
- 桌面入口与远程部署使用同一程序和标定。部署后默认停车，手动START。

188项综合回归通过，覆盖转向、车身坐标、道路历史、弯道衔接、电机通信和横道礼让。历史图像测试固定拍摄时标定，避免镜头重新标定后误用新投影。当前姿态的右偏、摆动改善和连续横道实例切换仍需实车综合复验。v0.6.24单次转弯后礼让实录：约40厘米处确认横道，距车身约16厘米停稳，等待约3.46秒继续。旧通过状态屏蔽后续横道由日志复现；v0.6.25用同段实录图像和真实旧状态回放，能独立确认并接近新事件。回放不等同于连续两次实车礼让通过。

### 历史验证记录

**v0.6.19-speed-200，2026-10-25**，分支 `experiment/speed-200`，200档已部署并完成用户实车反馈。

当前稳定基线标签为 `baseline-v0.6.17`。旧基线 `baseline-v0.6.15` 继续保留；横道速度反馈 v0.6.16 尚未部署，已单独保存。

- 道路中线采用局部参数二次曲线，支持双边线与单边线推算。
- 已接受的当前观测置信度至少 0.65、当前追踪点有观测支持、有效运动估计及车身余量检查通过，并连续稳定一个电机响应周期（当前 0.4 秒）后，允许提高巡航指令。基准 60，直道上限可配置；随曲率增加撤销额外提速。200档实验将 `straight_cruise_pwm` 设为 163，加既有起步补偿后的实际输出上限为 200/255。Maix指令、回执校验与UNO固件上限同步更新；基准巡航仍为60，横道控制未改动。旧尾迹仍按原规则过期，但不再用整条历史路径最弱的点否定一个有当前观测支持的追踪点。偶发运动估计失效立即取消该次额外提速，连续道路观测的计时单独保留；实际道路丢失会重新计时。条件变弱退回基准巡航，不因此新增停车。横道和寻路限速保持独立。
- 使用自适应前瞻追踪控制，支持有限历史预测及有道路余量约束的小幅转向寻路。前瞻距离按电机响应时间平滑变化，每张图仅更新一次，防止瞬时测速波动让追踪点在弯道前后跳变。中线及目标支持范围不做延伸。
- 横道礼让：接近、停车确认、约 3.3 秒等待、继续通过；刹车灯由 UNO 控制。
- 本版本修正横道前反复起停：只有停车距离的整个误差区间都在 20cm 之外，才允许再次接近。位置不确定时保持停车确认，不冒充已验证的合法停车。
- 网页提供实时原图、识别结果、地面投影，以及 START / STOP。部署后默认停车，手动 START 后无固定运行时长限制。

此前版本已实车跑完全程。v0.6.15 已完成 298 项巡线及横道测试；实测记录证明前瞻距离突变可以在同一中线上产生反向指令，固定几何回放验证平滑后消除了其中两次明显反向。v0.6.14 这一轮的记录未显示实际额外提速，横道前后仍有抖动，因此暂不继续加速。修正后的横道前后抖动已获用户正、反两个行驶方向的改善反馈。全速实验仍需实车对比，尚未证明整圈速度收益。此前 v0.6.13 提速试跑经用户确认到达终点、未压线或出界，但有明显停顿，未证明整圈提速；该轮存在障碍物影响，不能直接用它确定加速与停顿的因果关系。

上一档v0.6.17基线的实车测试：用户确认已到终点、全程未压线或出界。约55秒后画面进入地垫端部附近零速等待；首段采样最高实际输出109/255，额外提速有触发。横道停车位置未验证通过，不能算完整规则任务成功；本轮与原速没有同起点同方向的有效计时对照，暂不声称整圈提速。此版本按用户要求合入主分支作为新基线；横道停车位置验证仍是已知限制。

150档试跑记录已保存：采样最高实际输出124/255，约52秒后零速等待，横道礼让验证通过；用户随后要求继续200档，未确认该趟终点及压线情况。150档仍保留在 `experiment/speed-150`，没有替换 `baseline-v0.6.17`。录下的120档与150档起点画面朝向不同，不据此声称整圈用时改善。

200档实车反馈：用户表示来回表现很好。可用日志记录到一次START，采样指令峰值159/255，首次活动至最后非零指令约49秒；横道出现停车位置未验证与等待超时记录。两方向均良好属于用户反馈，不冒充已独立录像验证的两趟；没有据此认定整圈提速收益。

## 当前接线

- MaixCAM2 UART4：A21 TX → 电平转换 LV1/HV1 → UNO A0 RX。
- UNO A1 TX → 电平转换 HV2/LV2 → MaixCAM2 A22 RX。
- 摄像头串口速率 9600；UNO USB 调试串口 115200。
- 刹车灯信号接 UNO A2。供电和地线按实际模块定义连接，3.3V 与 5V 逻辑通过转换板连接。

标定和车身尺寸针对本车；改变镜头安装位置或角度后需要重新标定。

## 本地测试

主机 Python 环境需要 NumPy 和 OpenCV。设备端程序使用 MaixPy，不能直接作为桌面 Python 摄像头应用运行。

```sh
python3 -m venv .maixpy/.venv
.maixpy/.venv/bin/python -m pip install numpy opencv-python
mkdir -p .maixpy/speed-profile
cc -std=c99 -O3 -fPIC -shared maixcam2/curve_follow/curve_fit_kernel.c \
  -o .maixpy/speed-profile/host_curve_kernel.so -lm
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  CURVE_NATIVE_LIBRARY="$PWD/.maixpy/speed-profile/host_curve_kernel.so" \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_curve*.py'
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_crosswalk*.py'
```

当前分支结果：263 项巡线测试、45 项横道测试通过；UNO本地边界与看门狗测试通过。新增测试验证Maix/UNO上限一致、200正反转回执、超限拒绝、饱和时轮速比例与原低速指令兼容性。部分历史实车录像仅保存在本机；依赖这些录像的测试在没有录像时会跳过。

## 生成部署程序

```sh
mkdir -p .maixpy
python3 maixcam2/curve_follow/build.py --drive
```

生成的 `.maixpy/install_curve_follow_drive.py` 通过已配置的 MaixPy 部署工具在设备上运行：备份旧版本、编译设备端 C 内核、启动应用，并检查多帧遥测与初始停车状态。省略 `--drive` 则生成强制预览版本。

UNO 使用 Arduino IDE 打开 `uno/uno_lane_drive/uno_lane_drive.ino`，开发板选择 Arduino UNO。

设备凭据、部署工具配置、完整录像、调试日志和旧固件备份保存在本机，不提交到 GitHub。仓库保留回归测试使用的精简样本。

独立直接启动按钮（v0.6.28）：网页“直接启动”和触屏START无需等待发车灯；仍使用同一道路、UNO、标定和任务启动检查。网页ARM保留等灯发车。STOP同时取消直接启动队列和等灯状态。远程部署通过START_LIGHT_DISARMED=1保持初始停车，正常桌面打开仍按runtime配置决定是否等待发车灯。

三圈比赛（v0.6.29）：`runtime.json.race.laps=3`。用户确认的起点横白线与龙门架几何共同确认计圈位置；要求新一轮从该线前方发车。起步经过这条线不计圈，此后每次返回并确认车头越过整条线，计数加1；第三圈立即停车、取消等灯，不自动重启。网页和画面显示0/3到3/3。STOP保留计数供查看，新一次直接启动/灯光发车清零并开始新比赛。
计圈不按帧或每条白线累加：横向宽条纹须符合地面尺寸，且与指定龙门架相对位置一致；跨线需近处观察和携带不确定度的运动估计支持，同一龙门架访问只消费一次，离开该视野后才允许新访问。未确认的越线不猜测圈数，网页提示并记录unverified_crossings。龙门架位置/尺寸或相机姿态变化后须重新核对race标记参数。当前已通过实拍检测回放和三圈状态机测试，尚需实车三圈验证，不能据此声称已实际跑满三圈。

全画面发车灯（v0.6.30）：不再使用固定屏幕框。在320×240完整原图搜索发光区域，按已采集的灯芯/光晕外观进行多尺度匹配，黄色框跟随实际检测位置。灯已亮着也能确认，稳定约0.35秒后才请求发车；道路、UNO和计圈起点检查继续生效。普通红色物体、均匀亮区、多个匹配灯和突跳候选不能直接发车。当前外观模板来自本场发车灯，换灯具或明显改变曝光后需重新验证。直接启动、STOP和三圈规则保持；部署初始解除等灯，车轮为零。

启动就绪修正（v0.6.31）：ARM只开启灯光确认，允许先等灯，不依赖道路/UNO先就绪；真正发车仍检查当前中线、连续5帧有效道路、及时指令、车身余量、UNO及计圈起点。有效道路质量采用模型原有measurement_quality，confirmation_quality保留用于冲突道路替换，不再把已接受的稳定道路永久挡在启动门外。STOP清除旧灯光结果，页面显示识别暂停，不再把旧结果显示为当前灯灭。

统一发车（v0.6.32）：人工直接启动与发车灯仅触发来源不同，实际发车共用道路、及时指令、车身余量、标定、UNO和横道配置检查；两者均开始同一套巡线、横道礼让、三圈计数。计圈线确认不再作为发车前置条件：若发车时看不见，计圈器进入SEEK_DEPARTURE边巡线边等待识别；首次确认通过该线不计圈，此后三次返回计数并停车。建议从计圈线前开始；未识别的越线不能凭空计数。

白线独立计圈（v0.6.33）：用户确认龙门架已移走，仅以横向白线计圈。检测使用车道内横向线段提议、整条白带覆盖率及前后灰路对比，兼容白线连接路边线、阴影和短段道路观测；纵向斑马条、窄反光和路边线不能单独触发。候选在测得的帧间运动补偿后连续3帧确认，跨线用带不确定度的地面平面判断，首次跳过、三次返回停车。重复计数保护在整车驶离白线、白线持续离开画面后解除，不再要求驶过龙门架。画面显示COUNT LINE与白线确认状态。
发车灯加入已采集的LED阵列外观，与旧过曝光晕共同匹配；90%匹配门槛和连续亮灯0.35秒规则不变，灭灯对照不应触发。两种发车入口共用同一巡线及三圈任务。部署默认停车、未布防。实地三圈计数仍需验证，回放/合成运动测试不能替代实地结果。

发车灯识别与耗时修复（v0.6.34）：整幅图提议发光区域，按区域尺度断开细线连接；匹配允许有界宽高变化和图像边缘可见部分，轻度平滑兼容LED阵列过曝成光斑。灯芯亮度、局部对比和外围亮度渐变联合排除白纸、普通亮块；90%匹配门槛和0.35秒连续确认不变。先粗后细搜索并缓存模板，避免每个亮点穷举所有尺度。已识别亮灯但画面处理超时会明确显示等待及时画面，两种发车入口仍共用道路、UNO和横道启动检查。部署初始停车、未布防；计圈检测未在此版本修改。
