# robot-car

miniAuto 麦克纳姆轮小车：MaixCAM2 巡线与任务识别，Arduino UNO 驱动电机及刹车灯。ESP32-S3 上仰识别龙门架发车灯，通过 Wi-Fi 给 Maix 发送本轮发车信号；Maix 下视巡线，路牌识别尚未实现。

## 当前入口与操作

当前优化基线为 **v0.7.1**，驾驶实现与 `v0.6.102-backport.1-simple.7`（`32fcf5f`）一致。2026-11-12 实车反馈明显改善，后续从 `v0.7.1` 标签继续单项优化。保留原 DWPP 速度基准，按实测非线性模型只增加外轮 PWM；转向补偿与提速资格分开，补偿使用车体速度约束并复核自己的车身轨迹。转向增益为 0.95，弯中曲率系数为 1.05；PWM 硬件上限为 255，模型仍受有效标定范围约束。`DRIVE_TRACE` 逐帧记录发布输出、最新成功 UNO 回执及对应发送时刻、模型分配和车身运动，便于后续对照。

**v0.7.2-test.4 修正第三项“弯道按标定模型分配两轮”在弯中过早退出。** 仅第三项开启时，跳过近处道路曲率过小或反向的旧补偿门槛，继续按当前追踪／DWPP 转向目标分配，并检查实际车身弧线。开关字段仍为 `bend_inner_reduction`，保留①短暂测速丢失时保持转向、②横道恢复阶段使用 DWPP。第三项以当前转向目标为输入，从已测轮对范围联合求左右 PWM；基准 PWM 在模型域外时，也可搜索域内合法轮对。短暂测速缺失且仍有合格近期运动证据、可靠当前中线时，按本帧中线重新计算转向。道路、任务、置信度、车体速度、横向加速度、加速斜坡和实际弧线余量检查仍有效，不改运行速度参数，不替换起步控制。

三个开关默认关闭，全部关闭时保留 v0.7.1 的驾驶控制基线；版本标识、界面和诊断日志随试版更新。只允许停车且未 ARM 时修改，控制循环确认后生效；STOP 保留已生效选择并取消待处理修改，重启程序恢复全关。页面可一键恢复基线，每轮 START、CONTROL 和逐帧 DRIVE_TRACE 均记录实验组合。①冻结旧差速曾延迟收转向，本轮保持关闭；②仅针对 `RECOVERY_PASSING`。建议先全关做基线，再停车、只开③，在相同条件下比较同一弯的外侧压线、出弯修正和内轮持续转动情况。离线回归与模型结果不能证明实车已改善。

## 当前行为

计算：复用上一帧成功测量的光流角点，逐帧保留质量检查，失败后重新找点；计圈条纹按候选批量采样。完整有效白边走等价快速路径；计圈候选先批量计算几何再执行原有检查，横道检测复用标定坐标与公共掩码；保留四轮亮度/反光判定、所有候选及阈值。未发车时不重复构建启动时本就会清空的寻路地图，行驶中仍逐帧维护。

道路：相邻但被明确绿色隔开的道路不再强行配成同一对左右边界；仅在当前图像证明分属两个连通路面、较近道路唯一明确且已有路沿和车身检查通过时采用近路。详见[停车策略与超时根因](docs/停车策略与横道停留修复-20261107.md)。针对绿色场地、白边和灰色路面的固定配色，灰路面分类排除绿色；当前可见的明确绿色可反证旧道路和旧寻路地图，白色横纹及不可见区不否决或刷新历史。详细对照见 [路面识别评估](docs/路面识别评估-20261104.md)。在完整相机帧中提取灰色道路与白边，使用地面投影、参数二次曲线和单双边法线偏移构建中线，自适应前瞻追踪。远处支持不再只瞄准最近点，而沿同一条已识别曲线连续提前取点，改善横向弯道转向过迟；保留范围限制、减速和车身检查。当前完赛优先模式持续保存经运动补偿的预测中线；有地图证据的恢复寻路受车身余量与运动误差限制；只有实际发布对应转向脉冲后才等待停稳，未发出的提案不占用停稳等待。当前启用 `road_search.finish_priority=true`：中线持续保存，质量、定位误差、新旧线分歧和路面反证共同影响置信度；统一规划器据此限速，保留非零慢行参考，新观测确认后恢复加速；缺少测速时使用同一比例限制轮速，不重复套固定恢复档。没有可用指令时，允许四次一轮的短脉冲左右探路，每次最长0.12秒、逻辑峰值30，每轮最长6秒。未找到路就从新发零速指令和停稳回执重新开始下一轮，交替首转方向，不再因一次搜索失败永久等待。虚拟车身边界冲突允许这些低速恢复转向，接受可能压路沿扣分；不会凭空生成前进路径。当前已见连续道路支持、目标和转向指令均有效时可直接低速接回；其它情况仍需模型确认或连续五帧。实测视觉静止与新鲜零速回执连续成立时，探路间隔可由0.75秒缩短到0.25秒；缺失运动证据时保留原等待。每个动作仍有短租约；多轮累计方向和位移不保证归零，也不代表已验证周边空闲。横道任务、STOP及硬件保护继续拥有最终输出。

发车：ESP32上仰识灯，Maix下视巡线。默认全画面定位，也可在独立预览页用四条黄线手动保存灯面范围；不再限制青色定位框。正式流程是初始灭灯时ARM、裁判亮灯、随后熄灯；亮灯连续至少4帧且300ms，之后至少60%灯面像素变暗、连续至少3帧且0.4秒，才产生本轮信号。比较固定灯面与其曝光补偿后的基准，邻近计时数字不纳入灯面；自动定位模型只在找灯阶段运行。Maix收到确认后锁存出发许可，道路和电机就绪后发车；ESP32之后离线、重启或崩溃不撤销许可。STOP或完成目标圈数并最终停车时清除。两板通过车内Wi-Fi传递首次确认，不依赖电脑。时序及验证范围见[灭亮灭说明](docs/发车灭亮灭时序-20261109.md)。

横道：检测重复白条，以车身最近点约10–15cm为制动目标；按车身到横道的实际距离缩短速率计算制动，计入转弯时最近车角的运动，平行横道的位移不算接近速度。v0.6.91以距离区间、制动距离及响应时间限制接近速度，不因超过1秒没看全横道、固定精度或预测里程阈值单独停车。首次至少4条确认，已确认事件允许3条条纹经布局匹配与多帧确认重新定位；视觉持续确认静止并有零速回执及红灯时保留位置误差，不随等待无限增长。光流缺口保守扩大距离区间，恢复后按剩余刹车余量决定能否继续。尚未取得合法停位时，若有当前距离区间、道路及停稳证据且仍有刹车余量，则恢复接近，早停计时清零。合法停位一旦取得便保持停车，不做微调。只有不压线、整车最近距离小于20cm的停位已验证，且红灯、零速回执及视觉停稳连续计满3.2秒，才交还巡线。位置未知、可能压线或停得过远不能靠等满时间标记为合法礼让；当前完赛优先模式立即进入未验证低速恢复，明确保留未通过状态并允许主动寻路，不因信心不足先停车等待。已按明确位置发起的横道礼让仍停3.2秒；若证明持续不全，按零速回执计满同一3.2秒后低速继续，标记未验证，不追加等待或重复停留。明显运动、缺失光流、视觉长间隔或回执/红灯丢失仍中断停留计时；离线回归不代表实车停距已验收。

v0.6.89依据19cm现场记录校正零输出制动模型为0.20m/s²，平顺接近仍采用0.08m/s²规划，避免将温和减速误作实际刹停能力。刹停窗口、定位误差和礼让完成条件保持，详见[制动校正](docs/横道制动校正-20261110.md)。

v0.6.90开启统一速度规划的正常巡线接管测试，依据前方连续可见道路、曲率、外侧轮和制动距离生成速度上限，再用实测前进速度调节轮速幅值。横道及证据不足的恢复场景保留已验证控制；所有任务和电机保护仍优先。38秒基线已保存为`baseline-v0.6.89`，实车对比留到2026-11-11，详见[接管范围与回退](docs/统一速度规划接管-20261110.md)。

计圈：按指定横向白线计数。实际发车后首次可靠识别的白线，若连续识别起点在30秒内（含第30秒），本次越线不计圈；若超过30秒，则首次实测越线计为第1圈。之后独立越线正常计圈；单纯超时不增加圈数，ARM等灯不开始这30秒计时。规则和验证见[首次白线判断](docs/首次计圈白线30秒判断-20261107.md)。目标由网页现场输入（默认2圈）。达到所设圈数并确认最后一次越线后，以正常巡线速度累计40cm实测车身前向行程，再直接停车；已删除5秒计时，不做终点慢速对位。测距使用地面光流、车身参考点和累计误差，倒车抵消行程，原地转动与电机输出时间不充当米数。白线越线确认帧不追补之前的行程，因此计距触发及滑行会使实际停车距离略大于40cm；当前没有编码器。最终停车清除本轮发车许可。

速度：转向修正期间按平均与峰值驱动努力限制加速，避免一边加速迫使另一边意外刹低；连续左右微调不再逐步丢失油门。现有峰值、道路限速与STOP优先保持。已确认的温和路段按前瞻点和车身前向检查范围内的逐点最低质量规划基础油门，避免无关历史尾段拖慢；范围内的弱/旧观测仍限速。道路观测确认与单帧能否提速分开维护，临时短视距/远视距仍不提速，恢复足够支持后复用连续观测证据；弱观测、切路、失路、过时或长图像间隔仍重建确认。详见[稳定路段速度优化](docs/稳定路段速度优化-20261107.md)。加速爬升按连续有效命令的实际时间计算，避免低帧率拖慢；达到 300ms 间隔或 STOP 后重新起步，不积攒加速额度。当前道路连续确认、测速有效且车身余量允许时，基础档 PWM 135、稳定道路档 PWM 155，仍按曲率减速；正常直道基础上限 163，峰值补偿 37，最终输出不超过 200/255。预测及低信心路段由统一置信度速度包络限制，测速失效时也不撤销该限制；有余量验证的原地寻路保持60；失去地图或运动证据时，视觉探路每次逻辑 PWM 不超过 30，仍受峰值补偿与短租约限制。PWM 是驱动指令，不是实测转速；提速仍依赖当前道路、运动和车身余量；本档尚未通过整圈实车对比测时，不能当作已验证的最快速度。视觉预算 280ms 与电机通信看门狗保留。

现有实车记录包括多次完赛和正反向测试，但没有证明当前全部比赛任务均通过。计圈在运动估计失效、越线位置误差累积时仍可能漏计；该问题不属于本次代码清理的修复。当前白线后40cm停车是用户调试配置，与正式规则中的龙门停车不能直接等同；完整比赛任务尚未验证。

巡线接续、短时预测及设备计时对照见[优化记录](docs/道路接续与短时预测优化-20261107.md)。

## 接线与标定

- Maix UART4：A21 TX → LV1/HV1 蓝线 → UNO A0 RX；UNO A1 TX → HV2/LV2 紫线 → Maix A22 RX。
- 两端共地；转换板 LV 为 3.3V、HV 为 5V。UART 9600，UNO USB 调试串口 115200。
- 刹车灯信号接 A2，模块供电按已验证接法。
- 车轮轴距 11cm，镜头约在前轮轴，镜头到车头 2cm。当前投影已吸收横向安装偏置，不能再次平移。
- 改变镜头安装位置或仰角必须重新标定：以镜头正下方为起点，30cm、60cm 两条横线和 30cm 内侧净宽组成矩形。当前 `calibration.json` 不用于历史照片测试。

## 本地验证

Python 需要 NumPy 和 OpenCV；以下命令使用项目已有环境。原生核与 Python 参考实现均保留。

```sh
mkdir -p .maixpy/build
cc -std=c99 -O3 -fPIC -shared maixcam2/curve_follow/curve_fit_kernel.c \
  -o .maixpy/build/host_curve_kernel.so -lm
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  CURVE_NATIVE_LIBRARY="$PWD/.maixpy/build/host_curve_kernel.so" \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
c++ -std=c++11 -Iuno/uno_lane_drive tests/test_drive_safety.cpp \
  -o .maixpy/build/test_drive_safety
.maixpy/build/test_drive_safety
```
