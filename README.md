# robot-car

miniAuto 麦克纳姆轮小车：MaixCAM2 巡线与任务识别，Arduino UNO 驱动电机及刹车灯。ESP32-S3 上仰识别龙门架发车灯，通过 Wi-Fi 给 Maix 发送本轮发车信号；Maix 下视巡线，路牌识别尚未实现。

## 当前入口与操作

当前源码版本 v0.6.75，Maix 桌面名称 **AAA**，应用 ID `robot_curve_follow`。 完赛阶段布尔状态已修复为可序列化类型，避免日志异常导致提前保护停车和网页退出，见[修复记录](docs/完赛阶段退出修复-20261107.md)。
设备最近使用的 IP 为 `10.73.124.209`；调试网页为 `http://<设备IP>:8000/`。地址可能随网络改变，私有设备配置放在 `.maixpy/`，不入库。

- 摄像头屏幕完整显示画面，底部左侧 ARM、右侧红色 STOP，右上角 EXIT；STOP 停车并取消 ARM，EXIT 停车并退出。
- 网页可现场输入目标圈数（1–100整数，初始值取配置，当前默认2圈），点击ARM或直接启动时生效；ARM后及行驶中固定目标，先STOP才能重新设置。网页提供直接启动、ARM 等待信号、STOP；底部另有常驻红色 STOP。两种启动方式使用相同的道路、通信和比赛检查，区别仅为是否等待视觉信号。
- 从桌面打开应用或远程部署后，默认未 ARM、保持停车；手动点击 ARM 后才等待信号。
- 每轮出发许可初始化为假；ARM先确认稳定亮灯，再确认熄灯。Maix收到确认后锁存许可，ESP32后续离线不影响本轮运行；STOP或最终完成圈数停车才清除许可。

网页预览 JPEG 质量为 85，后台仅编码最新帧，不堆积旧画面；网页发布上限为 10 帧/秒，本机屏幕为 5 帧/秒；巡线与触屏仍逐帧处理，启动或停车状态变化立即刷新本机屏幕。仅到期才绘图，按刷新完成时间安排下次，不追补旧帧；实际帧率受视觉处理与网络速度限制。状态请求串行，弱网时不重复堆积；ESP32发车服务独立使用81端口、预览使用80端口，后台页暂停图传；图片挂起会超时重连，状态不可达不再直接判为ESP32硬件离线；巡线使用压缩前的原始 BGR 帧，图像亮度归一化与反光边界过滤保持启用。

## 当前行为

计算：复用上一帧成功测量的光流角点，逐帧保留质量检查，失败后重新找点；计圈条纹按候选批量采样。完整有效白边走等价快速路径；计圈候选先批量计算几何再执行原有检查，横道检测复用标定坐标与公共掩码；保留四轮亮度/反光判定、所有候选及阈值。未发车时不重复构建启动时本就会清空的寻路地图，行驶中仍逐帧维护。

道路：相邻但被明确绿色隔开的道路不再强行配成同一对左右边界；仅在当前图像证明分属两个连通路面、较近道路唯一明确且已有路沿和车身检查通过时采用近路。详见[停车策略与超时根因](docs/停车策略与横道停留修复-20261107.md)。针对绿色场地、白边和灰色路面的固定配色，灰路面分类排除绿色；当前可见的明确绿色可反证旧道路和旧寻路地图，白色横纹及不可见区不否决或刷新历史。详细对照见 [路面识别评估](docs/路面识别评估-20261104.md)。在完整相机帧中提取灰色道路与白边，使用地面投影、参数二次曲线和单双边法线偏移构建中线，自适应前瞻追踪。远处支持不再只瞄准最近点，而沿同一条已识别曲线连续提前取点，改善横向弯道转向过迟；保留范围限制、减速和车身检查。短时盲区只使用有期限、经运动补偿的历史道路；有地图证据的恢复寻路受车身余量与运动误差限制；只有实际发布对应转向脉冲后才等待停稳，未发出的提案不占用停稳等待。看不清路且地图不能授权转向时，允许最多四次短脉冲左右探路，每次最长 0.12 秒，停稳后再尝试下一次；总时限 6 秒。道路模型已重新确认时复用其证据恢复，其它新鲜道路仍需连续五帧；未找到便保持停车。探路不代表已验证周边空闲；明确车身边界冲突或横道停车任务会阻止探路。

发车：ESP32上仰识灯，Maix下视巡线。青框 `[80,0,160,128]` 用于定位，中心 `(160,64)` 保持不变；黄色框显示锁定灯面的外包矩形，实际检测固定的分割像素。ARM后先连续4帧、至少300ms确认亮灯；灯面至少60%像素变暗，连续至少3帧且至少0.4秒确认后，Maix锁存出发许可，不再设置两秒有效期。道路和电机就绪后发车；ESP32之后离线、重启或崩溃不撤销许可。STOP或完成目标圈数并最终停车时清除。当前两板通过车内Wi-Fi传递首次确认，不依赖电脑。详见[出发许可锁存](docs/出发许可锁存-20261107.md)。定位框扩大与核验见[扩框记录](docs/ESP32定位框扩大-20261107.md)。

横道：检测重复白条，以车身最近点约10–15cm为制动目标；取消固定6cm/s龟速接近，只按距离、测距误差、制动距离及速度响应限制必要的接近速度。进入停车区间一次归零，不做末段对位；过快、距离不明或可能压线时仍提前停车。红灯、零速回执及视觉停稳共同计满3.2秒后立即交还正常巡线，位置验证与恢复流程共用同一段物理停留，不再另等一轮。短窗检查实际位移趋势，避免微小光流抖动反复重置；明显运动、缺失光流、视觉长间隔或回执/红灯丢失仍中断计时。合法停车要求不压线且最近距离小于20cm；位置未核实的异常礼让会单独记录，不能算作合法任务成功。详见[停车策略与超时根因](docs/停车策略与横道停留修复-20261107.md)。

计圈：按指定横向白线计数。实际发车后首次可靠识别的白线，若连续识别起点在30秒内（含第30秒），本次越线不计圈；若超过30秒，则首次实测越线计为第1圈。之后独立越线正常计圈；单纯超时不增加圈数，ARM等灯不开始这30秒计时。规则和验证见[首次白线判断](docs/首次计圈白线30秒判断-20261107.md)。目标由网页现场输入（默认2圈）。达到所设圈数并确认最后一次越线后，以正常巡线速度累计40cm实测车身前向行程，再直接停车；已删除5秒计时，不做终点慢速对位。测距使用地面光流、车身参考点和累计误差，倒车抵消行程，原地转动与电机输出时间不充当米数。白线越线确认帧不追补之前的行程，因此计距触发及滑行会使实际停车距离略大于40cm；当前没有编码器。最终停车清除本轮发车许可。

速度：加速爬升按连续有效命令的实际时间计算，避免低帧率拖慢；达到 300ms 间隔或 STOP 后重新起步，不积攒加速额度。当前道路连续确认、测速有效且车身余量允许时，巡航基准由 PWM 120 提至 140，仍按曲率减速；正常直道基础上限 163，峰值补偿 37，最终输出不超过 200/255。预测、弱观测、测速失效等未满足提速条件时仍用基准 120，有余量验证的原地寻路保持 60；失去地图或运动证据时，视觉探路每次逻辑 PWM 不超过 30，仍受峰值补偿与短租约限制。PWM 是驱动指令，不是实测转速；提速仍依赖当前道路、运动和车身余量；本档尚未通过整圈实车对比测时，不能当作已验证的最快速度。视觉预算 280ms 与电机通信看门狗保留。

现有实车记录包括多次完赛和正反向测试，但没有证明当前全部比赛任务均通过。计圈在运动估计失效、越线位置误差累积时仍可能漏计；该问题不属于本次代码清理的修复。当前白线后40cm停车是用户调试配置，与正式规则中的龙门停车不能直接等同；完整比赛任务尚未验证。

巡线接续、短时预测及设备计时对照见[优化记录](docs/道路接续与短时预测优化-20261107.md)。

## 代码组织与清理

当前代码使用 `robot` 包的明确模块边界：`core` 共享数值与策略，`perception` 生成单帧道路测量，`navigation` 管理历史道路和恢复，`tasks` 维护比赛任务，`control` 统一驾驶生命周期，`interface` 提供显示与网页。`main.py` 仅作为入口，配置归一化集中于 `config.py`。

已删除旧Tracker状态镜像、未使用的时间参数、全局拼接部署和旧启动器迁移补丁。有限视觉扫视已成为独立状态机；所有电机输出由控制会话统一发布，STOP优先于同帧启动及完赛事件。重复的标量测试副本已用冻结结果替代，测试共享构造器与数值参考分别放在 `tests/support` 和 `tests/reference`。具体职责及构建流程见 [应用说明](maixcam2/curve_follow/README.md)。

本次清理前工作副本保存在 `.maixpy/cleanup-20261103/before.tar.gz`；原有未提交修改和本地录像保留。源码提交不代表设备已更新，当前设备版本以网页 `/vision` 的 `app_version` 为准。当前相机姿态见 [标定记录](docs/标定记录-20261107.md)。

## 接线与标定

- Maix UART4：A21 TX → LV1/HV1 蓝线 → UNO A0 RX；UNO A1 TX → HV2/LV2 紫线 → Maix A22 RX。
- 两端共地；转换板 LV 为 3.3V、HV 为 5V。UART 9600，UNO USB 调试串口 115200。
- 刹车灯信号接 A2，模块供电按已验证接法。
- 车轮轴距 11cm，镜头约在前轮轴，镜头到车头 2cm。当前投影已吸收横向安装偏置，不能再次平移。
- 改变镜头安装位置或仰角必须重新标定：以镜头正下方为起点，30cm、60cm 两条横线和 30cm 内侧净宽组成矩形。当前 `calibration.json` 不用于历史照片测试。

## 本地验证

Python 需要 NumPy 和 OpenCV；以下命令使用项目已有环境。原生核与 Python 参考实现均保留。

```sh
mkdir -p .maixpy/build
cc -std=c99 -O3 -fPIC -shared maixcam2/curve_follow/curve_fit_kernel.c \
  -o .maixpy/build/host_curve_kernel.so -lm
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  CURVE_NATIVE_LIBRARY="$PWD/.maixpy/build/host_curve_kernel.so" \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
c++ -std=c++11 -Iuno/uno_lane_drive tests/test_drive_safety.cpp \
  -o .maixpy/build/test_drive_safety
.maixpy/build/test_drive_safety
```

部署用 `maixcam2/curve_follow/build.py` 打包，并用 MaixPy 技能助手运行生成的安装脚本。默认构建强制预览，`--drive` 允许正式驾驶配置，但安装后仍不 ARM、不发车。完整步骤见 `maixcam2/curve_follow/README.md`。

双摄分工、协议失效处理和历史回测见 [双摄发车信号评审](docs/双摄发车信号评审-20261106.md)。合并控制页直接由 Maix 提供，不依赖电脑。
