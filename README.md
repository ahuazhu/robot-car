# robot-car

miniAuto 麦克纳姆轮小车：MaixCAM2 巡线与任务识别，Arduino UNO 驱动电机及刹车灯。ESP32-S3 当前仅提供 USB 预览，路牌识别尚未实现。

## 当前入口与操作

当前源码版本 v0.6.58，Maix 桌面名称 **AAA**，应用 ID `robot_curve_follow`。
设备最近使用的 IP 为 `10.127.108.209`；调试网页为 `http://<设备IP>:8000/`。地址可能随网络改变，私有设备配置放在 `.maixpy/`，不入库。

- 摄像头屏幕完整显示画面，底部左侧 ARM、右侧红色 STOP，右上角 EXIT；STOP 停车并取消 ARM，EXIT 停车并退出。
- 网页可现场输入目标圈数（1–100整数，初始值取配置，当前默认2圈），点击ARM或直接启动时生效；ARM后及行驶中固定目标，先STOP才能重新设置。网页提供直接启动、ARM 等待信号、STOP；底部另有常驻红色 STOP。两种启动方式使用相同的道路、通信和比赛检查，区别仅为是否等待视觉信号。
- 从桌面打开应用或远程部署后，默认未 ARM、保持停车；手动点击 ARM 后才等待信号。
- 每次 ARM 以当前画面作为基准；发车后停止检测启动信号。STOP 取消等待，手动重新启动会开始新一轮计圈。

网页预览 JPEG 质量为 85，后台仅编码最新帧，不堆积旧画面；发布上限由 5 提至 10 帧/秒，实际受视觉处理与网络速度限制。状态请求串行，弱网时不重复堆积；巡线使用压缩前的原始 BGR 帧，图像亮度归一化与反光边界过滤保持启用。

## 当前行为

计算：完整有效白边走等价快速路径；计圈候选先批量计算几何再执行原有检查，横道检测复用标定坐标与公共掩码；保留四轮亮度/反光判定、所有候选及阈值。未发车时不重复构建启动时本就会清空的寻路地图，行驶中仍逐帧维护。

道路：针对绿色场地、白边和灰色路面的固定配色，灰路面分类排除绿色；当前可见的明确绿色可反证旧道路和旧寻路地图，白色横纹及不可见区不否决或刷新历史。详细对照见 [路面识别评估](docs/路面识别评估-20261104.md)。在完整相机帧中提取灰色道路与白边，使用地面投影、参数二次曲线和单双边法线偏移构建中线，自适应前瞻追踪。远处支持不再只瞄准最近点，而沿同一条已识别曲线连续提前取点，改善横向弯道转向过迟；保留范围限制、减速和车身检查。短时盲区只使用有期限、经运动补偿的历史道路；有地图证据的恢复寻路受车身余量与运动误差限制。看不清路且地图不能授权转向时，允许最多四次短脉冲左右探路，每次最长 0.12 秒，停稳后再尝试下一次；总时限 6 秒。看到连续五帧有效道路才恢复，未找到便保持停车。探路不代表已验证周边空闲；明确车身边界冲突或横道停车任务会阻止探路。

发车：只看顶部居中的 64×32 检测框，320×240 原图坐标为 `[128,0,64,32]`。ARM 时记录当前亮灯画面，只有同一区域稳定变暗才可触发，不要求完全熄灭；亮度差阈值 28、至少 512 像素，同一位置连续 4 帧且持续至少 0.6 秒。确认窗口固定第一个变化区域为基准，后续区域与其交并比须至少 0.6，抑制扫过框的反光和短闪。当前不使用颜色或灯具模板；固定、持续且与真实灯具有相同亮度变化的反光仍无法仅靠此判据区分。

横道：检测重复白条，接近后确认停车与红色刹车灯，等待约 3.3 秒再通行。合法停车要求车身不压横道、最近距离小于 20cm；识别到横道或完成等待不等于停车位置已验证，遥测分别记录。

计圈：按指定横向白线计数，起步首次跨线不计，此后每次确认跨线各计一圈，目标由网页现场输入（默认2圈）。达到所设圈数后确认车尾越线，再累计经连续电机回执确认的前进输出 5 秒停车；暂停、倒车、原地旋转、过期及失联间隔不计入。该计时确认的是电机输出，不能替代编码器测得的实际位移。

速度：当前道路连续确认、测速有效且车身余量允许时，巡航基准由 PWM 120 提至 140，仍按曲率减速；正常直道基础上限 163，峰值补偿 37，最终输出不超过 200/255。预测、弱观测、测速失效等未满足提速条件时仍用基准 120，有余量验证的原地寻路保持 60；失去地图或运动证据时，视觉探路每次逻辑 PWM 不超过 30，仍受峰值补偿与短租约限制。PWM 是驱动指令，不是实测转速；提速仍依赖当前道路、运动和车身余量；本档尚未通过整圈实车对比测时，不能当作已验证的最快速度。视觉预算 280ms 与电机通信看门狗保留。

现有实车记录包括多次完赛和正反向测试，但没有证明当前全部比赛任务均通过。计圈在运动估计失效、越线位置误差累积时仍可能漏计；该问题不属于本次代码清理的修复。当前亮度变暗触发和白线后定时停车是用户调试配置，与正式规则中的熄灯发车、龙门停车不能直接等同。

## 代码组织与清理

当前代码使用 `robot` 包的明确模块边界：`core` 共享数值与策略，`perception` 生成单帧道路测量，`navigation` 管理历史道路和恢复，`tasks` 维护比赛任务，`control` 统一驾驶生命周期，`interface` 提供显示与网页。`main.py` 仅作为入口，配置归一化集中于 `config.py`。

已删除旧Tracker状态镜像、未使用的时间参数、全局拼接部署和旧启动器迁移补丁。有限视觉扫视已成为独立状态机；所有电机输出由控制会话统一发布，STOP优先于同帧启动及完赛事件。重复的标量测试副本已用冻结结果替代，测试共享构造器与数值参考分别放在 `tests/support` 和 `tests/reference`。具体职责及构建流程见 [应用说明](maixcam2/curve_follow/README.md)。

本次清理前工作副本保存在 `.maixpy/cleanup-20261103/before.tar.gz`；原有未提交修改和本地录像保留。源码提交不代表设备已更新，当前设备版本以网页 `/vision` 的 `app_version` 为准。当前相机姿态见 [标定记录](docs/标定记录-20261104.md)。

## 接线与标定

- Maix UART4：A21 TX → LV1/HV1 蓝线 → UNO A0 RX；UNO A1 TX → HV2/LV2 紫线 → Maix A22 RX。
- 两端共地；转换板 LV 为 3.3V、HV 为 5V。UART 9600，UNO USB 调试串口 115200。
- 刹车灯信号接 A2，模块供电按已验证接法。
- 车轮轴距 11cm，镜头约在前轮轴，镜头到车头 2cm。当前投影已吸收横向安装偏置，不能再次平移。
- 改变镜头安装位置或仰角必须重新标定：以镜头正下方为起点，30cm、60cm 两条横线和 30cm 内侧净宽组成矩形。当前 `calibration.json` 不用于历史照片测试。

## 本地验证

Python 需要 NumPy 和 OpenCV；以下命令使用项目已有环境。原生核与 Python 参考实现均保留。

```sh
mkdir -p .maixpy/build
cc -std=c99 -O3 -fPIC -shared maixcam2/curve_follow/curve_fit_kernel.c \
  -o .maixpy/build/host_curve_kernel.so -lm
OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  CURVE_NATIVE_LIBRARY="$PWD/.maixpy/build/host_curve_kernel.so" \
  .maixpy/.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
c++ -std=c++11 -Iuno/uno_lane_drive tests/test_drive_safety.cpp \
  -o .maixpy/build/test_drive_safety
.maixpy/build/test_drive_safety
```

部署用 `maixcam2/curve_follow/build.py` 打包，并用 MaixPy 技能助手运行生成的安装脚本。默认构建强制预览，`--drive` 允许正式驾驶配置，但安装后仍不 ARM、不发车。完整步骤见 `maixcam2/curve_follow/README.md`。
